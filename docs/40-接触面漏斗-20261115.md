# 40 · 接触面漏斗：agent 到底有多难碰到题（2026-11-15）

> 读者 = 下一个统筹窗口 / 决策者。本文只回答一个问题：
> **我们的 agent 碰不到题，是瓶颈吗？** 结论：**不是主瓶颈，但有两处还在流血。**
> 同批数据的能力侧结论见 `docs/39-失败深层原因-20261115.md`，两者共用同一套口径。

---

## 0. 口径（先说清楚怎么算的）

| 概念 | 定义 | 数据源 |
|---|---|---|
| **run 行** | 结果 JSONL 里一行，`run_id` 去重后的**一次派单** | VM `/home/rjq/**/*.jsonl`，740 条 |
| **进入（entered）** | 该 run 的 `agents.db` 里 **≥1 条 `function_call`**——模型真的调用过工具 | 459 个 `agents.db` 只读连接 |
| **接触（contact）** | 目标类工具（`http_probe`/`tcp`/`route_map`…）或带 URL 的 `exec_command`，且输出**无**传输失败标记 | 同 docs/39 §3.1 口径 |
| **会话** | `agents.db` 里的一个 `session_id`，一次 run 可能有多个 | 462 个会话 |

两条分母必须分开说：**run 行**回答"派单有没有变成一次真实尝试"，**会话**回答"尝试里有没有连上题"。
混用会得出"一半的题碰不到"这种错结论。

---

## 1. 结论先行

1. **题级接触率 92.1%**（174/189 道有过结果行的题，至少进入过一次）。这不是瓶颈。
2. **run 级只有 50.1%**（371/740）进入 agent；但未进入的 369 条里 **262 条（71%）是 3 道题被重试了 233 次**——`compete` 的 B-23 连跳计数上线之前，state 里没有 `skips` 字段，调度器会对同一题无限重派。**已修复，11-14 同类只剩 15 条。**
3. **真正从未进入过的题：7 道**（全部是单次受害于平台抖动/隧道），另有 6 道 SECQA 设计上就是零工具。
4. **run 内的接触质量不是问题**：有判定的 346 场会话里 98.1–98.6% 是 `CONTACT_OK`，首次成功接触中位落在**第 1–2 次调用**。
5. 还活着的接触风险是**"整队静默失效"**类（凭据、配额、实例就绪），不是"agent 摸不到目标"。这类风险在 10 小时赛里会一次性烧掉整批派单。

## 2. 三层漏斗

### 2.1 派单层（run 行，n=740）

| 层 | 条数 | 占比 | 说明 |
|---|---|---|---|
| 派单 | 740 | 100% | 去重后的 run 行 |
| 进入 agent | **371** | **50.1%** | ≥1 次工具调用 |
| 进入且解出 | **206** | 27.8% | 进入组的解出率 **55.5%** |
| 进入未解出 | 165 | 22.3% | 能力侧，见 docs/39 |
| 未进入但判 correct | 9 | 1.2% | 零工具答题（见 §5 复核项） |
| 未进入且未解出 | **360** | 48.6% | 构成见 §3 |

### 2.2 会话层（n=462，只含真起了 agent 的 run）

| 结果标签 | n | ZERO_TOOL | NO_CONTACT | CONTACT_FAIL | **CONTACT_OK** |
|---|---|---|---|---|---|
| SOLVED | 206 | 0.0% | 1.5% (3) | 0.5% (1) | **98.1% (202)** |
| UNSOLVED | 144 | 0.0% | 1.4% (2) | 0.0% | **98.6% (142)** |
| UNKNOWN | 112 | 33.9% (38) | 5.4% (6) | 5.4% (6) | 55.4% (62) |

解出组与未解出组的接触质量**几乎相同**（98.1% vs 98.6%）——这说明失败不是"连不上"。

**接触的时机也不晚**：已接触的会话里，首次成功接触在调用序列中的位置中位为 **0.12（解出组）/ 0.04（未解出组）**，绝对值 1–2 次调用；25% 之后才首次接触的只有 8.4%/4.2%。

**失败组反而更慢**：中位调用数 40（未解出）vs 14（解出），中位目标调用 21.5 vs 9。时间花在**解题**上，不是花在**连接**上。

## 4. 需隧道 262 条的解剖（最大的一坨，也是最容易被误读的一坨）

| 维度 | 数值 |
|---|---|
| run 数 | 262（占全部未进入的 71%） |
| **不同题数** | **15** |
| 前三题 | SAMPLE-023（80）、SAMPLE-024（79）、SAMPLE-017（74）= **233（89%）** |
| 时间分布 | 11-13 一天里 239 条；11-14 15 条；其余 8 条散在 10-30/11-01/11-03 |
| 11-13 窗口 | 09:34 → 16:12，**约 30 秒一次重派** |
| 这三题最终解出 | SAMPLE-017 **1 次**、SAMPLE-023 **1 次**、SAMPLE-024 **2 次** |

**根因不是"隧道永远建不起来"，而是两个叠在一起的问题：**

1. **实例间歇可达**：同一题在 78–85 次尝试里有 1–3 次是干净 run，且解出过。靶面是 netns/`.internal` 型，平台侧放行不稳定。
2. **调度器无限重派**：`compete-state-run2` 的 state 里 **`skips: None`**——B-23 的连跳计数还没写入，判据永远是 0，于是每 30 秒重派一次，一整天。

**已修复的证据**：B-23 落地后，11-14 同类只剩 15 条（全是 AUTHORED-*），不再滚雪球。B-25 的 DNS 竞态重试（6×5s）也在这条路径上。

> 教训写在这里：**"35% 的派单白扔了"这句话本身是错的**。它是 3 道题 × 78 次重试的产物，
> 题级损失只有 3 道，而且这 3 道后来都解出来了。**看漏斗必须同时看 run 数和题数。**

## 5. 题级视角（n=189 道有过结果行的题）

| 分类 | 题数 | 占 189 |
|---|---|---|
| **进入过（≥1 次工具调用）** | **174** | **92.1%** |
| └ 进入且解出过 | 141 | 74.6% |
| └ 进入但从未解出 | 33 | 17.5% |
| **从未进入** | **15** | 7.9% |
| └ 零工具但解出过（6 SECQA + SAMPLE-005/020） | 8 | 需复核，见下 |
| └ **从未进入也从未解出** | **7** | 见下 |

（解出过的题共 149 = 141 + 8；8 道零工具题的"解出"不计入接触能力。）

**7 道从未进入也从未解出的题**（每道只有 1–3 次尝试）：

| 题 | 尝试 | 死因 |
|---|---|---|
| AUTHORED-6953BB87 | 3 | ProxyError / 503 启动失败 / 无可直连地址 |
| CYBENCH-017 | 2 | 两个实例都不可达（`*.node4.ctfy.run`） |
| CYBENCH-018 | 1 | `ConnectTimeout` 到平台 API |
| CYBENCH-019 | 2 | 实例不可达 + ConnectTimeout |
| CYBENCH-020 | 1 | ConnectTimeout |
| SQLILABS-017 | 1 | `not ready in 180s` |
| XBOW-070 | 1 | `not ready in 180s` |

**这 7 道是真损失**：不是能力不够，是**一次抖动之后就再没有第二次机会**。总量小（占 189 题 3.7%），
但机制值得记：单次派单的实例起不来 → 直接判失败 → 调度器按连败 defer。比赛当天如果赶上台面抖动，
损失的就是 1–3 道题 × 若干分。

**复核项**：9 条"未进入但判 correct"里，7 条是 SECQA（知识作答，合理），2 条是 SAMPLE-005/020
（`correct=True`、`flags_found=0`、零工具调用）。它们可能是真解（题目答案可直接推出），也可能是
sidecar 回灌；**未复核，不得当成接触成功或能力证据**。

## 8. 建议动作（预注册，不调预算）

| 动作 | 类别 | 验收 |
|---|---|---|
| **A. 派单 canary**：每批开跑前 1 次 LLM `max_tokens=1` + 1 次平台只读调用；失败即**停队并大声报错**，不把题判失败 | 接线类 | 单测：坏 key 时队列停止、题不进 `fails` |
| **B. not-ready 复用**：`not ready in 180s` / `两个实例都不可达` 后，**沿用同一实例**再等一轮，而不是销毁重起 | 接线类 | 单测：第二次探测成功则继续；总等待不超过原重试预算 |
| **C. 复核 9 条零工具 correct**（含 SAMPLE-005/020） | 仪表 | 给出"真解 / 回灌"判定并写台账 |
| 不做 | — | 不给隧道题加惩罚分、不因本次数据调 turns/wallclock |

**先做 A、B**：都是接线类（符合"一次只改一处"的例外条款），且直接对应 11-20/21 的硬风险。
C 只是清账，随时可做。

## 10. 边界

- 740 条是**全库所有 JSONL 去重**，包含练习/冒烟/测评混跑；不是同一实验设计下的样本，只看结构比例，不做因果。
- "进入"只证明**调用过工具**，不证明调用的是目标类工具；后者由会话级接触口径补足。
- 隧道子原因来自 error 字符串，**平台侧当时的真实状态不可回放**。
- 本轮结论与 `docs/39` 的 48 道从未解出题**不冲突**：那 48 道是"有标注的 389 条 run"口径，本文是 740 条全库口径；交集里只有 7 道是接触造成的。
