## 0. 结论先行

- **待判 34 项 = 参照系缺失 28 项 + 补位/替代候选 6 项；A 档 23 个工具、B 档 9 个工具、C 档 2 个工具。**
- 另有 4 项已经写进工作树但**尚未提交**：`gdb`、`strace`、`ltrace`、`capstone`。它们不计入 A 档，但必须在重建镜像前先提交，否则 HEAD 构建仍缺。
- A 档全量估算增加 **160–315 MB 压缩层**，镜像从 886 MB 约到 **1.05–1.20 GB**；中心估计约 1.1 GB。
- B 档全量估算增加 **2.4–5.3 GB 压缩层**，镜像约 **3.3–6.2 GB**；不建议全量，按题型分批。
- 100 GB 磁盘不是约束；**镜像拉取、解压、冷启动**才是。A 档在 100 Mbps 链路上约多 1.5–2 分钟拉取，20 Mbps 上约多 7–10 分钟。
- 最高优先级 3 个工具：**`pycryptodome`（含 `pycryptodomex`）、`z3-solver`、`Pillow`**。`binwalk` 紧随其后，因为 `file_triage` 已经会自动探测它。

关键判断：

1. `docs/14` 的 `gdb 17.1 / radare2 6.0.7 / binwalk / exiftool / z3 / pwntools / PIL` 是 **VM 宿主机安装记录**，不是 `docker/Dockerfile` 的交付镜像。把它当成镜像现状，会重复 worker E 的误判。
2. `gdb`、`strace`、`ltrace` 只在工作树 `docker/Dockerfile:31`，HEAD 没有；`capstone` 只在工作树 `requirements.lock:17`，HEAD 没有。

4. `capstone` 缺失不会让 `elfpeek` 崩：`src/ctf_strix/nonweb.py:1358-1373` 是可选导入，`:1715-1726` 会退回 `objdump` 提示。但反汇编和 gadget 质量会下降。

## 3. 缺口决策表

档位定义：

- **A**：轻量、运行时完全离线、装了就增强。可以是 apt 小包、pip wheel，或钉校验和的静态二进制。
- **B**：体积大或依赖重，或会显著增加攻击面/内存开销，必须按题型权衡。
- **C**：我们环境用不上，或不值得为它承担许可/依赖代价。

> 体积是**压缩层增量估算**，不是安装后磁盘占用；依据是 Debian 包和 manylinux wheel 的常见量级，未在本机实测。

2. **A 档不是「装了就解出」**。按防过拟合守则，任何能力改动都要在未参与改动的题上验证；本报告不提供题号、IP、路径或 flag 级结论。
3. **`--no-deps` 是最大接线风险**：`Dockerfile:43-48` 照 lock 单装；`pwntools/volatility3/RsaCtfTool/sympy` 的传递依赖如果不进 lock，import 仍会失败。建议单独生成 `requirements.ctf.lock`，包含完整传递闭包和哈希。
4. **apt 包名/版本会随基础镜像漂移**：`python:3.12-slim` 是浮动标签；`7z` 可能叫 `7zip` 或 `p7zip-full`，`radare2` 是否在源里要构建时确认。建议钉 Debian snapshot 或至少在 CI 里打印 `apt-cache policy`。
5. **第三方静态二进制要钉 SHA256**：`stegseek`、无 apt 包时的 `radare2`、`RsaCtfTool` vendor 源码都属于这一类；不要让构建脚本无条件 `curl | tar`。
6. **攻击面**：`ImageMagick/ffmpeg/tesseract/binwalk` 都解析不可信文件；容器虽以 `agent` 非 root 运行（`Dockerfile:67,71`），仍应限制 seccomp/资源，并避免把外部二进制放到 PATH 前面。
7. **`gdb/strace/ltrace` 的 ptrace 能力**：构建成功不等于容器里能调试；需要真机 `gdb -batch`/`strace` 冒烟。
8. **`stegseek` 没有字典就是半件工具**：不要默认把 rockyou 塞进镜像；按题面线索生成小字典，或只在确认需要时挂载。
9. **`playwright` 不等于浏览器**：`requirements.lock:79` 只有 Python 包，Dockerfile 没有浏览器二进制；不要把它算作 web 浏览能力。
10. **镜像体积的验收口径**：构建后记录 `docker images --format '{{.Size}}'`、registry manifest 的 compressed size、冷启动时间；本报告只能给估算，不能替代实测。
