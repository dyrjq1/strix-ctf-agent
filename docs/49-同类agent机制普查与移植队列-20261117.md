# 49 · 同类 agent 机制普查与移植队列（2026-11-17）

> 用户定的方向：找**单模型、无外网、非竞速**的开源 CTF/安全 agent，至少五个，
> 逐个把机制套到我们身上，改前存档、改后做对比实验。
> 本文只记录**机制**与**移植计划**；实验结果一律回流 `docs/11-实验台账.md`。

约束（筛选口径，缺一不取）：

- 单模型可跑：不需要 controller/critic/多模型编排；
- 可在**无外网**环境完成主循环：不依赖 web search / 在线知识库 / SaaS；
- 非竞速：不针对排行榜速度做设计，机制在「几十次调用 + 几百秒」的预算内仍有意义。

## 1. 普查结果（6 个仓库 + 此前的 OpenSage）

| # | 仓库 | 架构 | 匹配 | 对我们的有效增量 |
|---|---|---|---|---|
| 1 | **OpenSage / SageCTF**（见 docs/48） | 动态造 agent + 广播 + 自动唤醒 | 单模型✔ 无网✔ 非竞速✔（但单题 3400 次调用、5h） | 空上下文子 agent（已移植：`race_spawn`）；广播（未做，预算不容） |
| 2 | **D-CIPHER**（NYU-LLM-CTF/nyuctf_agents） | Planner–Executor，执行体每任务空上下文，强制交付摘要 | ✔✔✔ | 空上下文 + 摘要回传（已有 `attempt_digest` 等价物）；终局单写者（已有 finish_guard） |
| 3 | **EnIGMA**（= SWE-agent v0.7 的 CTF 模式） | 单 agent shell REPL + 观测入口压缩 + 交互式子进程 | ✔✔✔ | **封顶落盘 + 回读指针**（中段不丢）；**持久 TCP 会话**（读-算-写协议） |
| 4 | **PentestGPT** | Supervisor/Executor + 确定性计划内核（SQLite 状态机） | ✔✔✔ | **类级硬拒绝 + 操作失败不扣账**；证据必须回执到原始观测 |
| 5 | **hackingBuddyGPT** | 单循环 + 原生 tool calling + 端点探索 FSM | ✔✔✔ | **端点结构派生阶梯 + 查询参数面**；**漏洞清单 × 端点桶工作清单** |
| 6 | **cai**（aliasrobotics） | OpenAI Agents SDK fork + 分层提示 + handoff | ✔✔✘（并行/多 agent 部分不适配） | **失败→下一步纠偏 notice**；续跑建议（需额外 LLM 调用，暂缓）；确定性近期事实卡（多数已有） |
| 7 | **HackSynth** | Planner/Summarizer 双模块，摘要即状态 | ✔✔✔ | 仅一条增量：**命令级硬超时**（先核实我方 exec 语义） |

三份研究的共同结论：**能搬的都是确定性代码层的东西，提示词层已被本项目反复证伪**
（§4.241 剂量到了行为没变；§4.246 并行零触发）。

## 2. 移植队列（按「解出率杠杆 / 风险」排序）

| 序 | 机制 | 来源 | 改动面 | 开关 | 状态 |
|---|---|---|---|---|---|
| Q1 | 端点结构派生：实例 / 子资源 / 查询参数面，只出未请求过的 | hackingBuddyGPT | `discovery.py` + tests，100–400 行 | 进 `route_map` 输出，无需开关 | codex 实施中 |
| Q2 | 失败→下一步 notice（405/401-403/不可达/空 200/超时/TCP 关闭，每类每 run 一次） | cai | 新模块 `recovery_notice.py` + 共享接缝，<100 行 | `CTF_RECOVERY_NOTICE`，默认关 | 已实现 + 18 单测绿，待 A/B |
| Q3 | 类级硬拒绝：同类机制 N 次无新观测即拒；操作失败（超时/连接）不计数 | PentestGPT | `enum_guard.py`，<100 行 | `CTF_CLASS_BLOCK`，默认关 | 待实施 |
| Q4 | 封顶输出落盘 + 回读指针（内容哈希命名） | EnIGMA | `context.py`，<100 行 | `CTF_SPILL`，默认关 | 待实施 |
| Q5 | 清单 × 桶：按端点结构给「该测什么」，渲染进现有拒答/台账 | hackingBuddyGPT | 新模块，100–400 行 | `CTF_WORKLIST`，默认关 | 待实施 |
| Q6 | 持久 TCP 会话（open/send/close，单会话纪律 + 截止时间闸门） | EnIGMA | `nonweb.py`，100–400 行 | 只在 `kind=tcp` 注册 | 待实施（web 收益窄，排后） |
| Q7 | 命令级硬超时审计：确认 `exec_command` 是硬 kill 还是仅轮询 | HackSynth | 审计先行，可能零改动 | — | 审计 |

排序理由：

- Q2 直击已测瓶颈（失败题墙钟被同一方向吃掉；模型看到 405/401 仍换名字不换机制），
  且零模型调用、可完全离线判定「该响时响 / 不该响时不响」；
- Q3 把「软提示」升级为「硬拒绝」，与 Q2 互补：Q2 给下一步，Q3 拦住原地打转；
- Q4 是纯粹的上下文保真修复，风险最低，但只在「长响应中段藏答案」的题上有杠杆；
- Q5 依赖 Q1 的端点结构，排在后面避免重复派生；
- Q6 只对 TCP 题有效，练习赛全 web，放到后面。

## 3. 实验协议（每个机制一条）

1. **改前存档**：`backup/<slug>-20261117/` + 一个 git commit（worktree 分支，不推 main）。
2. **单测先行**：正例逐类覆盖 + 反例（不该响时不响）；全量 `pytest tests` 不低于基线
   （2026-11-17 基线 1977 passed / 7 skipped，新增用例后同涨）。
3. **接线双入口**：官方 `agent.py` 与评测 `scripts/run_strix_ctf.py` 必须同面；
   共享接线点是 `tool_trim.install_ctf_toolset`（§4.249 的教训）。
4. **A/B 口径**：同题、同预算（25 turns / 280s 基准，medium 放大到 40 / 420s），
   先看**机制是否触发**（spawn 计数 / `[NEXT]` 计数 / `[trim] … installed`），
   再看停因、调用数、token、解出。
5. **判定**：触发=0 → 机制不可达，先修可达性；触发>0 且无收益 → 噪声，撤；
   触发>0 且有收益 → 保留并写台账回滚路径。
6. **不做**：用留出集调参；针对某题写死字符串；只调预算。

## 4. 不适配清单（已评估，别再试）

- 多模型编排（cai handoff、SageCTF 多模型、HackSynth Planner/Summarizer 双模型）：
  单模型下等于把一次调用拆两次，墙钟 ×2。
- 摘要即状态 / 按龄裁剪（HackSynth、EnIGMA history_processors、D-CIPHER 老化）：
  本项目实测缓存命中 95.7%→57.8%、等效成本 ×6，已回滚。
- 在线资料/RAG/字典爆破：无外网；字典爆破被 enum_guard 判停滞。
- VSCode/gdb/Ghidra 专用工具链：题面几乎全 web，且与现有 `exec_command` 重合。
- few-shot 黄金轨迹：过不了命名测试，撞防过拟合红线。
- 强制 `tool_choice="required"`：实测纯文本轮仅 0.5%，已撤销。
