## 2. 部署（按顺序，每步有失败判据）

### 2.1 传包与完整性

```bash
# 本地 → VPS（427M，约 2–5 分钟）
scp -r vps-bundle ubuntu@<VPS>:~/
ssh ubuntu@<VPS>
cd ~/vps-bundle
sha256sum -c MANIFEST.sha256 --quiet && echo BUNDLE_OK
```

失败判据：任何 `FAILED` 行 → 重传，不要在 VPS 上"就地修"（会与 MANIFEST 分叉）。

### 2.2 解包

```bash
bash ~/vps-bundle/bootstrap.sh ~/deploy
# 期望最后一行：DEPLOY_OK /home/ubuntu/deploy
```

bootstrap 做五件事：解 python → 解 repo → 解 venv 并把 venv 指回新路径 →
改写 shebang → 解 debs 到 `deploy/tools` 并补 soname 符号链接 → 拷 sqlmap。

### 2.3 系统依赖与提权（**bootstrap 不装这些**）

`vpn.py` 走 `sudo -n ip/wg/dig` + `/usr/local/sbin/ctfvpn-wg`。宿主缺一件，
所有 vpn 接入的题就永远连不上，症状只是"超时"。

```bash
sudo apt-get update
sudo apt-get install -y iproute2 wireguard-tools dnsutils curl git
sudo bash ~/deploy/strix-ctf-agent/scripts/install_vpn_sudoers.sh
# 期望：两行自检 OK，末尾卸载说明
```

> 注意：sudoers 白名单写的是 `/usr/bin/wg`，所以 **wg 必须是 apt 装的宿主包**；
> bundle 里的 `deploy/tools/usr/bin/wg` 只作为 PATH 工具，不能走 sudo。

### 2.4 自检闸门

```bash
bash ~/vps-bundle/vps_preflight.sh \
  --deploy ~/deploy --bundle ~/vps-bundle --lanes-conf ~/lanes.conf
# 期望末行：PREFLIGHT_RESULT_OK（fail=0；pass 数随车道数变化，排练机基线 30+）
```

任何 `FAIL` 都不许开跑。最常见三类见 §6 故障表。

## 3. 车道配置

格式一行一车道：`名字|LLM_API_BASE|LLM_API_KEY|模型名`。凭据只进子进程 env，
不进 argv、不落 state、不打日志。

```bash
cat > ~/lanes.conf <<'EOF'
# 名字|base|key|model   —— 开赛当天填三家
vendorA|https://<base-a>/v1|<KEY_A>|<model-a>
vendorB|https://<base-b>/v1|<KEY_B>|<model-b>
vendorC|https://<base-c>/v1|<KEY_C>|<model-c>
EOF
chmod 600 ~/lanes.conf
```

模型名必须与厂商当天真实暴露的名字**逐字一致**，而且**大小写敏感**。11-18 排练机
实测（同一把 paratera key，同一分钟内）：

| 写法 | 结果 |
|---|---|
| `DeepSeek-V4.1-Flash-1017` | 200 |
| `deepseek-v4.1-flash-1017`（全小写） | **403**（网关把名字规范化成 `…-P029` 再判） |
| `deepseek-v4.1-flash`（别名） | 400 no healthy deployments |
| `DeepSeek-V4-Pro-0813` / `MiMo-V2.6-Pro` | 200 |

所以：**以 preflight `lane probe` 的回显为准**，不要凭记忆或上次的写法照抄。

## 4. 启动

```bash
cd ~/deploy/strix-ctf-agent
export PF_TOKEN=<平台 token>          # 只在本会话，不写文件
export PYTHONPATH=$PWD/src:$PWD/vendor/src
export STRIX_RUNTIME_BACKEND=local LITELLM_LOCAL_MODEL_COST_MAP=True STRIX_TELEMETRY=false
export LLM_MAX_TOKENS=8192            # 部分网关缺参会报误导性 400

# ⚠️ 这两行不能省。bootstrap.sh 不写 ~/.bashrc，compete.py 也不自己设 PATH；
# 车道子进程继承的是**启动它的这个 shell** 的 env（compete.py:915 `{**os.environ, ...}`）。
# 少了第一行，干净 VPS 上 agent 的 exec_command 找不到 gdb/nmap/rg/sqlmap（它们只在
# bundle 的 tools 树里）；少了第二行，bundle 里的二进制找不到自带库（如 nmap 要 libpcre.so.3）。
export DEPLOY=~/deploy
export PATH="$DEPLOY/tools/usr/bin:$DEPLOY/tools/usr/sbin:$PATH"
export LD_LIBRARY_PATH="/lib/x86_64-linux-gnu:/usr/lib/x86_64-linux-gnu:$DEPLOY/tools/usr/lib/x86_64-linux-gnu:$DEPLOY/tools/lib/x86_64-linux-gnu${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"

# 自证：三条都必须有输出
command -v rg && command -v gdb && command -v nmap
```

# 1) 只看队列，不派单
.venv/bin/python scripts/compete.py --token "$PF_TOKEN" \
  --competition <cid> --state-dir ~/compete-state --lanes 3 \
  --lane-config ~/lanes.conf --dry-run

# 2) 正式开跑（nohup，日志分离）
nohup .venv/bin/python scripts/compete.py --token "$PF_TOKEN" \
  --competition <cid> --state-dir ~/compete-state --lanes 3 \
  --lane-config ~/lanes.conf --turns 25 --wallclock 300 \
  --until "2026-11-20T20:00+08:00" \
  > ~/compete.log 2>&1 &
```

- `--lanes 3`：平台配额 3；留余量就 `--lanes 2`（默认）。
- `--race-first N`：开赛前 N 秒把队首题同时派给所有车道先解先停。**默认 0**，
  要开就在开跑时给，窗口截止时刻落 state-dir，中途重启不重置。
- **不要**加 `--allow-pools` / `--ignore-platform-solves`（那两个是练习场自测用的）。
- `--turns/--wallclock` 是 easy 档基数；medium ×1.6/×1.5、hard ×2.4/×2.3 自动放大。
  想压预算必须同时给 `--max-turns/--max-wallclock` 硬顶，否则设小预算会被悄悄放大。

## 5. 开赛头 30 分钟：VPN 端到端（唯一硬未知）

平台侧交互式题按 `vpn_endpoint.config_url` 下发 WireGuard profile。这条链
今天只在排练机上验证到"能力具备"，**没有在真 VPS 上跑过**。30 分钟内按此顺序验：

1. 起 1 个实例（web/交互式），记下 instance id。
2. 取 profile：`GET /api/v1/instances/{id}/vpn-config`（batch_eval 内部同路径）。
3. 在 VPS 上让 `ctf_strix.vpn.VpnTunnel` 起隧道（或让 batch_eval 跑一题，
   它在 `access=vpn` 时自动起）。
4. 判据：`sudo -n wg show` 里 `latest-handshakes` 非 0；`ip -4 route` 有该题网段。
5. 拿实例入口 URL curl 一次，期望不是 404/超时。

三种结果的处理：

| 现象 | 判断 | 动作 |
|---|---|---|
| 握手成功、页面可达 | A4 达标 | 正常开跑 |
| `Operation not permitted` / 无 wireguard 接口 | 容器缺 CAP_NET_ADMIN | 记 `SKIPPED(需隧道)` 计数；按 `docs/47` F12 的备用接入（`tls_sni` 直连）试一题，能通则继续，不能通就只跑非 vpn 题并向组委会报障 |
| 握手一直 0 | 端点/中转问题 | 换实例、`CTF_VPN_RELAY` 中转各试一次；仍失败按上行处理 |

## 6. 监控与故障速查

三条只读命令（每 10 分钟看一眼就够）：

```bash
tail -50 ~/compete.log                                  # 派单/停放/失败分类
wc -l ~/deploy/strix-ctf-agent/strix_runs/*/results*.jsonl 2>/dev/null | tail -3
ls -lt ~/deploy/strix-ctf-agent/strix_runs | head          # 有没有新 run 目录
```

| 症状 | 最可能原因 | 处置 |
|---|---|---|
| 所有车道 401/403 | 厂商会话过期（当天有效，但会掉） | 换 key 重写 `lanes.conf`（600）；`lane probe` 复验 |
| 400 且报文提到 max_tokens | 网关要求显式 max_tokens | 已默认 `LLM_MAX_TOKENS=8192`；确认子进程 env 里在 |
| 429 / `Rate limited by upstream API` | 并发超配额（练习场 cap=3；第 4 个起必现） | 降 `--lanes`；**不要**重试风暴 |
| 平台 503 / 实例起不来 | 平台侧故障 | 降并发、等 5 分钟；把 `report_instance_issue` 用上 |
| `SKIPPED(需隧道)` 连续出现 | VPN 链路（见 §5） | 按 §5 表 |
| 车道跑完一轮就空转 | 队列被 defer | 看 `compete.log` 的 defer 理由；deferred 会在 solves_count 上涨 3 时回捞 |
| 所有宿主命令 `LIBSYSTEMD_* not found` | **bundle 库遮蔽宿主库（11-18 已修）** | 确认用的是打过补丁的 `bootstrap.sh`/`lane_launch.sh`（宿主目录在前） |
| agent 的 `exec_command` 里 `gdb/nmap/rg/sqlmap: command not found` | 启动 shell 没带 bundle 的 `PATH`（bootstrap 不写 `.bashrc`） | §4 的两行 export；11-18 起 `compete.py` 自己在 bundle 布局下也会补（`ensure_bundle_tool_env`），日志首行有「bundle 工具已挂进 PATH」即已生效 |
