## 5. 卡 vs 工具（判定规则）

**规则**：≤5 步、用现有工具、无跨轮状态 → **卡**；≥5 步机械动作、需跨轮状态、或缺原语
→ **工具**。卡片必须带四件：触发观测、点名真实工具的步骤、出口条件、一条判别测试。

| 类 | 机器可复用性 | 判定 |
|---|---|---|
| 已知 CVE 适配 | 版本→PoC→三个可变点（路径/编码分阶段/回显 oracle），全用 `http_probe`+`exec_command` | **卡** |
| 认证/设计逻辑 | 枚举状态机→记录可观测差异→重放/并发/跳过/跨账号引用 | **卡** |
| 供应链安装面 | 找入口与安装源→按命名规则准备包→触发安装→轮询→执行 | **卡**（若 B 臂显示"流程对、机制卡"再升工具） |
| 密码学 oracle（026） | 查询→解析位数→跨多轮统计恢复；跨轮状态 | 工具候选，**仅 1 道目标**，不动 |
| pickle allowlist（010） | 探允许的 reducer 集合→组合 gadget；跨轮状态 | 工具候选，**仅 1 道目标**，不动 |
| JWT/JWKS（010）、异常 oracle（028）、origin_trust（094） | 各 1 道 | 先各复跑一次（零代码），再判 |

## 6. 首批：三张卡

按"一次一处"纪律**串行实施并各自 A/B**；卡片是独立内容文件，撤文件即回滚。

**卡 A · 已知 CVE 适配链**
- 触发：响应头/静态资源/错误页给出产品+版本，或框架错误页给出 CVE 线索。
- 步骤：①`http_probe` 抓版本特征与错误页原文；②列出该 CVE 的**三个可变点**（入口路径、
  载荷编码/分阶段、回显 oracle）；③先做"让目标回显一个我们控制的随机串"的最小验证；
  ④再上完整利用；⑤失败时**只改一个可变点**并记录对照。
- 出口：拿到 flag/命令回显，或三个可变点各自验证失败。
- 判别测试：一次请求能否让目标回显我们控制的随机串（证明编码/解码方向正确）。

**卡 B · 认证逻辑（2FA / 账号合并 / 找回）**
- 触发：多步认证流程（注册→登录→OTP/找回→绑定/合并）且响应有可比较差异。
- 步骤：①`http_probe`+`route_map` 枚举全部认证端点与状态机；②每一步记录可观测差异
  （状态码、长度、字段、时序）；③分辨"值校验"与"流程校验"：跳过步骤、复用同一码、
  并发重复提交、把 A 的对象引用到 B 的会话；④合并/绑定类用两个受控账号分别准备，
  观察哪一侧属性被覆盖。
- 出口：拿到高权限会话或 flag。
- 判别测试：同一个 OTP/令牌换一个步骤顺序是否仍被接受（可重放/可跳过 = 流程缺陷）。

**卡 C · 供应链安装面**
- 触发：出现"安装/部署/扩展"动作，或响应里出现内部包索引名。
- 步骤：①定位安装入口与安装源（内部 PyPI/npm 镜像、包名与命名空间规则）；②按规则准备
  同名（依赖混淆）或近似名（抢注）包；③触发安装并轮询结果；④从安装产物侧拿执行
  （`setup.py` / postinstall / import 期执行）；⑤把"执行→读 flag"固定成一条命令。
- 出口：拿到命令回显或 flag。
- 判别测试：安装日志里出现我们包的构建/分发记录（证明安装源可控）。

## 7. 验证设计（每张卡独立预注册）

- **臂**：A = 卡片不在技能包；B = 卡片在位（其余一律不变）。
- **题集**：目标 3 道 + 同类已解出 5 道（供应链只有 3 道已解出，补 2 道同类从未跑题，共 8 道）。
- **主判据**：B 臂目标解出 ≥1，且 A 臂目标解出 = 0。
- **副判据**：零回归组 B 解出数 ≥ A；单次解出花费 ≤1.5×A。
- **迁移**：达标后第二批用该类"从未跑"题（CVE 7 / 认证 28 / 供应链 2），**不碰留出集**。
- **成本**：约 8 题 × 2 臂 = 16 run/卡，3 车道串行约 1.5–2.5h/卡；11-20 前可跑完两卡。
- **不达标即撤卡**，不写进镜像。
- 11-19 之后不再上新卡，只做已达标卡片的回归。
