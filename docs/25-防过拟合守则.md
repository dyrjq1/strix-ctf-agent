# 防过拟合守则

> 适用：所有影响评测结果的改动（prompt / guard / 技能 / 预算 / 工具面 / 镜像）。
> 违反 §5 任一条 → 直接 `rejected`，不进台账。

---

## 1. 总则

> **任何改动，必须在它没参与过的题上验证过，才算改完。**

没通过这句话的改动不叫"有效"，叫"在这批题上有效"。两者在日志里一模一样，
唯一的区分手段是换一批它没见过的题再跑一次。

---

## 2. 实况（2026-11-01 实测口径）

| 项目 | 数 |
|---|---|
| 跑过的不同题 | **56**（CTFARENA 48 + CYBENCH 6 + SAMPLE 2）|
| 跑次 | **102**（另有 488 次选择题跑次，已下线）|
| CTFARENA 解出 | **39 / 已测 48（81.2%）/ 全 115（33.9%）** |
| 封存集污染 | 旧 20 道里 **4 道**已脏，已整批重抽 |

> 数字来源与口径见 `22-覆盖矩阵与对标.md` §1–§2。**不要再引用 794/383/411 当作本赛事题量。**

**一条容易走歪的现状**：练习套件榜单上我们 `rank 13 / 88`（score 49），
但 **14 支 `entrant_kind=agent` 队全是 0 分 0 尝试**，前 3 名是人类手工打满。
所以 rank 13 **不代表落后**，只代表"agent 赛道只有我们在跑"。
**禁止**为了 rank 好看去调参——那是拿榜单分数当训练信号，比拿题号调参更隐蔽。

问题不在"56 道够不够"，而在这 56 道同时承担了三个角色：**定位问题、验证修复、验收效果**。
三道工序用同一批题，等于自己出题自己判卷。

CTF 场景下过拟合不表现为"记住 flag"，而是三种更隐蔽的形态（现状为实测判定）：

| 形态 | 长什么样 | 我们的现状 |
|---|---|---|
| 答案过拟合 | 硬编码路径 / flag 格式 / 端口 | **干净**：技能包零题号，`flag_extract` 是通用正则 |
| 失败模式过拟合 | 规则只匹配某道题的失败方式 | **仍有**：`enum_guard` 关键词表来自单题行为，且对 043 的**生成式枚举完全失效**（`enum_keys=4, enum_hits=0`）|
| 预算过拟合 | 轮次/超时刚好够这批题 | **已量化**：成功 p50 只需 60–70s，失败 p50 达 267s（medium）/ 551s（hard） → 预算不是瓶颈，**失败题给了时间也解不出** |

预算过拟合这条现在可以放宽一点：实测成功题 p90 是 253s，撞墙钟的 6 次里只有 2 次成功。
真正的瓶颈是**方向选择**，不是时间。但这不等于"预算不用管"——见 §3.3。

## 3. 五条细则

### 3.1 封存留出集：20 道，开发期禁跑

从"**agent 没跑过 且 本队没提交过**"的题里抽，写进 `docs/22` §5.3，标注种子与池子大小。

| 分层 | 题数 | 理由 |
|---|---|---|
| web easy | 8 | 主力盘，先看基础能力退化 |
| web medium | 8 | 正赛主力区间，最能分辨"拟合"与"泛化" |
| web hard | 4 | 天花板，只看不要求过 |

**禁令**：开发期（调 prompt、加 guard、改预算）一律不许跑。
跑一次它就变成训练集，永久失效，必须补抽。

**唯一允许运行的时刻**：定稿前用最终版本跑一次，跑完**不准再改代码**，只记录结果。
这一次运行 = 前面所有改动的联合审计。

### 3.2 每条改动标级：G（通用）/ S（特化）

| 级 | 定义 | 处置 |
|---|---|---|
| **G** | 能用一句**不含题目信息**的话描述 | 正常流转 |
| **S** | 描述里必须出现题号/具体路径/具体字符串 | 附「触发条件」，赛后 24h 内复查是否删除 |

- `G`：拿到代码执行后立刻去找 flag 文件
- `G`：见 401 才要求先走登录流程，纯注入题不强制（自带例外条款，仍算通用）
- `S`：`/api/coins` 别刷超过 4 次 → 必须写清"这是 CTFARENA-018 的形态，赛后复查"

**S 级不是禁止，是标记。**

### 3.3 预算参数不得单独调（已实测支撑）

四项（时间/轮次/并发/token）禁止作为独立改动提交。必须依附在一个能力改动上，
并写清"为什么这个能力需要更多预算"。

必答三问：

1. 这个数字的**物理依据**是什么（平台下发？协议规定？还是"这批题平均耗时 × 1.2"）？
2. 如果是"这批题算出来的"，那它就是拟合，**必须在留出集上重算**。
3. 调小之后，原本能过的题挂了几道？

> **已有实测答案**：40 轮上限下，成功题 p90 = 253s / 峰值 74k token（上下文 1M）。
> 也就是说 25→40→60 轮的分层没有证据支持，只是把失败题拖得更久（失败 p50：medium 267s / hard 551s，max 815s）。

### 3.4 一次只改一处

同一次提交改两个东西，归因就废了。例外：接线类修复（工具没注册、变量名写错、路径拼接错）
可以合并——它们的正确性由"有没有生效"判定，不需要 A/B。

### 3.5 关键改动要做消融

影响面大的改动（guard、prompt 主段落、工具面）改完**撤掉再跑同一题**：

- 撤掉后**变差** → 有效 ✅
- 撤掉后**没变化** → 噪声，删掉。留着只增加维护面和 prompt 长度
- 撤掉后**变好** → 方向反了，立刻回滚

> **本项目已有一次实证**：上下文"按龄裁剪"消融后，缓存命中率从 95.7% 掉到 57.8%，
> 等效成本从 10.9 万涨到 68.5 万（见 `docs/21`）。它是这轮唯一被数据否决的改动。

## 4. 两个判据（30 秒内能做完）

### 4.1 命名测试（`proposed` 态）

写下改动的一句话描述，**不许出现题号、IP、具体路径、具体 flag 字符串**。

- 写得出来 → 大概率 G 级，放行
- 写不出来 → S 级，必须标触发条件

### 4.2 迁移测试（`ab-tested` 态）

改动在**参与开发的题**上提升 X%，在**留出集**上提升 Y%。

| 情况 | 判读 | 处置 |
|---|---|---|
| X、Y 同向且量级接近 | 真提升 | 合入 |
| X 明显、Y 接近 0 | **过拟合** | 打回重做 |
| Y 为负 | 有害 | 立即回滚 |

判据线：**Y < 5 个百分点 → 一律视为过拟合**，不管 X 多漂亮。

## 5. 四条红线

1. **不许对着失败日志改 prompt 里的具体字符串。**
   看到 agent 卡在 `/admin.php` 就在 prompt 里写"试试 /admin.php"——这条一破，后面所有改动都不可信。

2. **不许用留出集调参。**
   跑过一次、看了结果、然后改代码 → 这批题作废，必须重抽。这条最难守，因为诱惑最大。

3. **不许把"这批题全绿"当成验收通过。**
   唯一验收口径：留出集分数 + 锚题没退化。开发题全绿是必要条件，不是充分条件。

4. **不许拿榜单名次当优化目标。**
   名次由别人的进度决定，不由我们的能力决定。练习榜上 14 支 agent 队全是 0 分，
   "升到第 1"只说明对手没跑，不说明我们强。分数只能从题面里挣。

## 6. 生命周期闸门

```
proposed ──[命名测试 §4.1]──→ adr → implemented → container-verified
    → ab-tested ──[迁移测试 §4.2]──→ ledgered ──[消融 §3.5]──→ merged/reverted
```

| 态 | 新增动作 | 不做的后果 |
|---|---|---|
| `proposed` | 命名测试 + 标 G/S | 不知道自己在拟合 |
| `ab-tested` | 补留出集结果（或写明"未跑，原因 X"）| 提升无法归因 |
| `merged` 前 | 大改动做消融 | 噪声越积越重 |

## 7. 抽样命令（可复现）

池子必须同时排除：agent 跑过的、本队提交过的、QA-only、对抗类套件、零解出的题。

```python
import json, random, collections

cat     = json.load(open("extract/catalog_full.json"))
touched = set(json.load(open("extract/touched_all.json")))        # agent 跑过的
subs    = json.load(open("extract/submissions.json"))
TEAM    = "e8d2cb0d-5721-42b5-969c-59f7fe368d35"
mine    = {s["challenge_id"] for s in subs if s["team_id"] == TEAM}   # 本队提交过（含人工解）

QA   = ("CTI-MCQ", "MMLU-CS", "SECQA")
EXCL = ("AWD-", "GAUNTLET", "GENERATED-", "SAMPLE-",
        "CAPTCHABENCH", "AUTOPENBENCH", "AGENTBENCH", "AGENT-DEFENSE")

pool = [c for c in cat
        if c["category"] == "web" and not c["is_qa_only"]
        and not c["id"].startswith(QA)
        and c["id"] not in touched and c["id"] not in mine
        and (c.get("solves_count") or 0) >= 1            # 别人解得出的才算可评测
        and not any(c["id"].startswith(e) for e in EXCL)]
pool.sort(key=lambda c: c["id"])

series = collections.defaultdict(list)
for c in pool:
    series[c["id"].rsplit("-", 1)[0]].append(c["id"])     # 按系列分组，保证跨系列覆盖

random.seed(20261101)                                     # 种子写死
TARGET = {"easy": 8, "medium": 8, "hard": 4}
diff   = {c["id"]: c["difficulty"] for c in pool}

picked, used = [], collections.Counter()
# 第一遍：系列规模降序，每系列每难度取 1（同系列最多 2 道）
for d in ("easy", "medium", "hard"):
    for s in sorted(series, key=lambda s: -len(series[s])):
        cands = [x for x in series[s] if diff[x] == d]
        if not cands: continue
        if sum(1 for p in picked if diff[p] == d) >= TARGET[d]: break
        if used[s] >= 2: continue
        picked.append(random.choice(cands)); used[s] += 1
# 第二遍：剩余按难度补齐
left = [x for s in series for x in series[s] if x not in picked]
for d in ("easy", "medium", "hard"):
    need = TARGET[d] - sum(1 for p in picked if diff[p] == d)
    if need > 0:
        picked += random.sample([x for x in left if diff[x] == d], need)

print(len(pool), "候选 →", len(sorted(picked)), "道封存")
print(sorted(picked))
```

**必须用这个两遍法，不能用裸 `random.sample`。** 裸抽样在 262 道池子上会把 8 道 easy
全部抽进 SQLILABS（该系列 easy 题最多），留出集就变成"只考 SQL 注入"。
当前代码已实测**逐字复现** `docs/22` §5.3 的 20 道，改动任一参数都会对不上。

首次执行结果：池 **262**（easy 71 / medium 138 / hard 53）→ 抽出 20 道，已写入 `docs/22` §5.3，台账见 `docs/11` §4.26。
台账记一行：

```
HELDOUT-SEAL · 2026-11-01 · 20 题 · seed=20261101 · 开发期禁止运行
```

### 7.1 补抽规则

封存集任一道被跑过（调试、误跑、"就看一眼"都算），立刻补抽：

1. **种子不变**，同一 `random` 序列往下取
2. 新题号**追加**到清单末尾，不删改原清单（否则无法审计抽了几次）
3. 台账记 `HELDOUT-RESEAL · 原因 · 换出 X · 换入 Y`

补抽次数是纪律指标：**超过 5 次说明流程已失效**，停下来先解决流程问题。

> 本项目现状：旧封存集 20 道里 4 道污染，已整体重抽 1 次（1/5）。

## 8. 一页速查

| 问题 | 答案 |
|---|---|
| 改完怎么算改完？ | 留出集上跑过，且没退化 |
| 怎么判断过拟合？ | 命名测试：写不写得出不含题目信息的一句话 |
| 留出集能跑几次？ | 开发期 0 次，定稿前 1 次，跑完不改代码 |
| 预算能单独调吗？ | 不能，必须依附能力改动 |
| 撤掉改动没变化？ | 删掉，它是噪声 |
| 提升多少算真提升？ | 留出集 ≥5 个百分点 |
| 开发题全绿算通过吗？ | 不算，只是必要条件 |
