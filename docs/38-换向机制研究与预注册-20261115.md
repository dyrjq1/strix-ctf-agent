# 38 · 换向机制：专业做法、候选设计与预注册（2026-11-15）

> 触发：用户指令「先想办法解决换向问题（这个问题应该不只是我们有，可以去查查专业的怎么解决），
> 和其他缺口，是否有效要通过实测数据来判断」。
> 本文只做三件事：**外部怎么解**、**我们改成什么样**、**事先写死怎么算有效/无效**。
> 判据在 §5，先于任何代码与任何测量结果写成。

## 0. 口径

- 「换向」定义（本文全程）：一次**机制族（mechanism class）**的切换，而不是换一个 payload、
  换一个路径、换一个参数——那些是同一假设加大剂量。
- 外部资料来自 2026-11-15 的公开检索。**除特别标注外均为摘要级转述**（arXiv 原文直连被
  域名策略拦住），引用时按「检索转述」对待，不当成逐字结论。
- 内部数字全部来自已有 artifact（docs/32、docs/37、台账 §4.186–§4.195），零新 token。

## 1. 我们现在的换向能力，量出来是什么样

| 观测 | 数字 | 含义 |
|---|---|---|
| `enum_guard` 的 MECHANISM / stall 提示 | 解出组 8/150 vs 失败组 19/149，中位出现位置 **73–77%** | 提示出现得太晚，且「出现」与「解出」负相关 |
| `journey_guard` 换向提示 | `journey_hits` **4/207 场** | 近乎不响 |
| `negative_guard` 注入 | `groups` 77/99 场非零，注入 **0/99** | 有判据、无输出；`groups` 是**不同 (参数,输出) 对的个数**，非零只说明命令在跑，不代表凑满 K |
| `progress_guard`（S2 结构停滞） | 44 场**零触发**；重放 23/23 对账 | 判据本身测不到「停滞」 |
| 提示词里已有的反枚举建议 | `prompt.py` `_SCAN_QUICK` 明确写了「更大字典是同一假设」 | **建议层已写过，没起作用** |
| 失败 run 的时长 | 成功 p50 60–70s；失败 p50 267s / 551s | 失败不是更快放弃，而是更久地重复 |

一句话：**我们有「阻止收工」的守卫（finish_guard 60/212 场，有效），没有「阻止在错误方向上
继续投入」的机制。** 现有的换向提示要么不响、要么响在预算快烧完的时候。

## 2. 外部怎么做（按「控制点在哪」分类）

### 2.1 把「还有哪些没试」变成可见状态 —— PentestGPT / 任务树系

- **PentestGPT**（USENIX Security '24）：核心是 Pentesting Task Tree（PTT），把渗透过程
  显式建成树，由模型标记完成度；它的价值不在「智能」，而在**让模型每次都能看到哪个分支
  没做**。代价：树由模型自己维护，模型忘了更新就失效。
- **MITRE ATT&CK 派生确定性任务树**（OpenReview `x4sdXZ7Jdu`）：不靠模型自觉，预先定义
  阶段枚举，按阶段推进。转述结论是确定性编排在**弱模型**上收益最大。
- **Isozaki et al.（ACM 2025）对 PTT 的批评**：树结构对强模型是负担、对弱模型才是脚手架。
  这与 `docs/36` 的三层判断一致（建议层随能力衰减，事实层不衰减）。

对我们的映射：**「哪些类还没试」是事实**（可以从调用历史数出来），不需要模型自省。

### 2.2 把探索空间压小，让「换向」变得不必要 —— EnIGMA

- **EnIGMA**（arXiv 2409.16165）：给 agent 交互式工具（调试器、可交互 shell、文件编辑），
  在 CTF 基准上大幅提升。它的逻辑不是「教模型换向」，而是**让每一步都能拿到可读的反馈**，
  从而不会在错误方向上盲走。
- 同一思路的工程共识（多篇 practitioner 文章，检索转述）：agent 死循环的三大根因是
  **没有尝试记忆、工具反馈不可读成 done/failed、没有真正的停止条件**。

对我们的映射：**把「本次调用产生了几个新状态」直接写进工具结果**，就是把不可读的反馈变成
可读的——这是事实层，不需要模型听从建议。

### 2.3 先定位失败步，再决定重规划还是剪枝 —— 失败归因线

- **DeFA**（arXiv 2610.01256）、**Cascade Failure Attribution**（2608.29646）、
  **Hierarchical attribution**（2602.23701）、**ICML 2025「Which Agent Causes Task Failures
  and When?」**：这一线的贡献是**定位**哪一步、哪个 agent 引入失败，并给出基准
  （2604.22708、2509.13782）。
- **空档**：这些工作回答「错在哪」，没有给出「发现错之后，重规划 vs 剪枝 vs 换类」的策略。
  检索没有找到专门讲 backtracking / 分支放弃策略的综述（2607.01641 讲的是无限循环的
  刻画，SSRN 7186738 是控制策略综述，都不含具体放弃规则）。

对我们的映射：**这正是我们可以自己定规则的地方**，但规则必须有离线前提支撑，不能拍脑袋。

### 2.4 规划对弱模型是精度脚手架 —— 2609.20804

- 转述结论：同一 planning 脚手架，对弱模型提升的是**正确率**，对强模型提升的是**成本**。
- 我们主线模型是 flash 级（`deepseek-v4.1-flash`），属于前者 ⇒ 确定性编排值得投。

### 2.5 合起来，专业做法给出的三个控制点

| 控制点 | 代表 | 形式 | 我们缺不缺 |
|---|---|---|---|
| ① 未试集合可见 | PTT / ATT&CK 树 | 状态外置 | **缺**（route_map 只有 55/120 场被调） |
| ② 反馈可读 | EnIGMA / 交互工具 | 事实注入 | **缺**（工具结果不说「产生几个新状态」） |
| ③ 放弃规则 | 失败归因线留下的空档 | 策略 | **缺**（enum 提示 73–77% 才响） |

## 3. 三个候选设计

> 全部按 `docs/36` 分层：**给事实的可以默认开**，**给建议的默认关 + 预注册**。
> 三个候选都先做零 token 前提测量，再决定写不写。

### A. 状态新颖度停滞 → 强制换类（事实 + 一条确定性指令）

- **判据**：把每次工具输出归一成**状态签名**（HTTP 状态码集合 + 输出里出现的路径集合 +
  JSON 顶层键 + 长度桶），同一个 run 内未见过的算「新状态」。当前机制族连续 K 次产出
  0 个新状态 ⇒ 判「本族耗尽」。
- **动作**：在该次工具结果尾部追加一段**事实句 + 一条指令**：
  「最近 K 次 `ffuf` 调用，输出状态签名完全相同（新状态 0 个）；已试路径 3,320 条；
  本族已标记为耗尽。下一步换一个机制族：<从未试过的类>。」
- **与现有 enum_guard 的区别**：现有判据是正文前 1500 字符的文本 diff，**看不见生成式枚举**
  （043 一次调用 3,320 个候选，`enum_hits=0`）；且它只在同一路径家族重复时计数，不判「有没有
  新信息」。A 的判据是**信息增量**，不是**字面重复**。
- **风险**：K 太小会把正常的多步验证打断；K 太大等于没做。K 值必须由 §5 的测量定，不许在
  A/B 中途改。
- **类别**：事实（新颖度可数）+ 建议（换到哪类）各一半 ⇒ 默认关，预注册。

### B. 机制族轮转表（未试优先）

- **判据**：从调用历史维护每族「已试次数 / 最近一次新状态时间」，当 A 判耗尽时，按
  **最少尝试 + 先验顺序**选下一族（例如：路径枚举 → 参数/方法探测 → 认证面 → 注入面 →
  源码/备份 → 逻辑/越权）。
- **形式**：纯确定性，不需要模型自省；可单独用，也可以作为 A 的输出。
- **风险**：先验顺序错了就是「系统地试错」。用历史 run 的族序列做离线校验：解出的 run 里
  换向后的族是否集中在少数几类。
- **类别**：建议层 ⇒ 默认关。
- **注**：B 单独没有触发源，实际是 A 的动作部分；单独测没有意义，合并为 A+B 一个改动。

### C. 假设台账 + 杀条件（模型自填）

- **形式**：每轮要求模型写「当前假设 / 什么结果算证伪」，工具结果里回显状态；证伪即标记死亡。
- **已知证据**：外部有 Intentest 类工作报告大幅提升（检索转述，未直连）；**内部**我们刚做完的
  `fact_ledger` 只覆盖 7% 的拒收，S2 判据零触发 ⇒ 这条线在我们这里是**低先验**。
- **结论**：**本轮不做**。若 A 被证伪再回头看 C，且必须先量「模型愿不愿意写假设」。

## 5. 预注册（写于 2026-11-15，先于测量与代码）

### 5.1 前提测量（零 token，历史 agents.db）

**问题**：历史上的失败 run 里，是否存在**足够早、足够长**的「零新状态」平段？解出的 run 是否
存在「平段后换族 → 新状态 → 解出」的案例？

| 编号 | 判据 | 门槛 | 不过怎么办 |
|---|---|---|---|
| P1 | 失败 run 中，结尾连续零新状态长度中位 | **≥ 5** | A 的 K 无处可设 ⇒ 停 |
| P2 | 失败 run 中，长度 ≥6 的平段在**前 50% 预算内**开始的占比 | **≥ 30%** | 检测到也太晚 ⇒ 停或改 K |
| P3 | 解出 run 中，「平段 ≥4 后换族且 10 次内出现新状态」的案例数 | **≥ 3** | 换向从未成功过 ⇒ 先查换向是否可能 |
| P4 | 全部调用里，签名此前已出现过的比例（基线重复率） | 仅作背景 | — |

**四条里 P1 与 P2 是硬门槛；P3 是「换向有用」的存在性证据，不需要比例高。**

### 5.2 A/B 判据（若前提过）

- **样本**：20 道已烧题（10 历史全败 + 10 历史解出），单开关 `CTF_SWITCH=0/1`，同模型
  （`deepseek-v4.1-flash`）、同预算（`--max-turns 40 --max-wallclock 420`）、串行。
- **主判据**：失败题上的**调用数中位**下降 **≥15%**。
- **护栏判据**：解出题的解出数**不低于基线 −1**；新增的提示不得让成功 run 的墙钟上升
  **>10%**。
- **仪表自检（先于读判据）**：实验臂里 `switch_injections > 0` 的 run 占比 **≥30%**
  （失败题子集）。若为 0，视同机制未生效，按 S2 的处理方式判「不采纳」，不做数字解读。
- **采纳**：主判据 + 两条护栏 + 自检全部满足 ⇒ 默认开；否则默认关，保留 `CTF_SWITCH=1`。

### 5.3 杀条件（任何一条成立立即停手）

1. P1 或 P2 不过：不存在可检测的平段（历史上 44 场 S2 零触发就是先例）。
2. A/B 里实验臂自检为 0：机制没被调用，差异必为噪声。
3. 主判据过了但护栏破：例如调用少了、解出数掉了 2 题以上 ⇒ 判「以放弃换便宜」，不采纳。
4. 需要为了过判据去改 K 或改先验顺序 ⇒ 视为对判据过拟合，本轮作废。

### 5.4 迁移测试

主判据通过后，用保留的 23 道未跑题按已预注册的哈希取 20（`060 089 076 111 092 101 104 105
100 070 109 062 005 110 068 099 066 075 056 071`），判据：**≥1 题且调用中位不升**。
这是冻结前最后一次大样本留出。

### 5.5 首次测量判决（2026-11-15，零 token，A 出局）

数据：443 个 `agents.db` / 405 场有调用 / 12,132 次调用 / 341 场可对上成绩标签
（解出 201、未解出 140），日期 10-30 → 11-15。口径与 §5.1 完全一致。

| 判据 | 门槛 | 实测 | 判决 |
|---|---|---|---|
| P1 失败 run 结尾平段中位 | ≥5 | **0**（只有 11/140 场 trail≥4） | **不过** |
| P2 前 50% 内出现 ≥6 平段的失败 run 占比 | ≥30% | **8.6%**（12/140） | **不过** |
| P3 平段后换族并解出的存在性 | ≥3 例 | 判据本身**失效**（见下） | 不可用 |

**判决：候选 A 按 §5.3 第 1 条停止，不写代码、不排 A/B。**

三条比杀条件更重要的发现：

1. **失败 run 不是「卡住了」，而是「更久、稍微更浪费地继续做」**：失败组调用中位 40 vs 解出组
   14（2.9×），浪费比例中位 20.1% vs 6.7%，最大平段中位 3 vs 1。把长度配到 20–60 次调用后，
   差异从 3× 缩到 1.3×（浪费 .185 vs .147，有 ≥4 平段的比例 .26 vs .21）。
2. **平段之后的换族率没有差别**：解出组 66.9%、失败组 66.5%。也就是说模型本来就在平段后换，
   「不换向」不是失败的分辨特征；再强的「强制换」也不会改变这个比例。
3. **P3 的「10 次内出现新状态」是恒真条件**：极大平段之后的第一次调用按定义就是新签名
   （1,423/1,423）。这条判据写错了，已作废，不得再用它论证「换向有用」。

口径警告：本次的「换族率」（中位 14.5 次/25 次调用）把 `write_stdin`、`finish_scan`、
`apply_patch` 当成了独立机制族，数字偏大；但第 1、2 条结论不依赖这个口径，只用**平段**与
**长度/浪费**，仍然成立。下一次若要用「换族」做变量，必须先剔除管路工具再统计。

## 7. 边界

- 状态签名是**我们自己的构造**，不是外部标准；它的可分辨性由 §5.1 的 P4 基线给出下限。
- 「新状态」不等于「有进展」：拿到新 404 页面也算新状态。A 只解决「完全无信息增量」，
  不解决「有增量但方向错」——后者要靠 B 的先验顺序，而先验顺序本身没有外部证据。
- 历史 run 的模型版本、预算与 A/B 不完全同分布（见 docs/32 §9.2 的教训）：前提测量只用于
  **判断存在性**，不用于预测效应大小。

## 8. 追加候选 D：修 `negative_guard` 的签名（优先于新写守卫）

### 8.1 两个互相竞争的假设

- **H1（我最初的假设，已被证伪）**：`response_signature()` 是逐字 sha1，而 `exec_command`
  结果里 `Chunk ID` / `Wall time` 每次都变，所以同命令三次的签名永不相同 ⇒ `K=3` 凑不满。
- **H2（实测支持）**：签名没问题，**行为本身不匹配判据**——模型几乎不把同一条命令
  原样重发三次。

### 8.2 修法（若 H1 成立才做）

签名前洗三条逐次噪声，语义数字（状态码、退出码、计数）全部保留：
`Chunk ID: \S+`、`Wall time: <num> seconds`、`/tmp/sandbox-\d+-\d+`。

### 8.3 预注册判据（离线重放，零 token）

在同一批 120 场 item 流上，把 `exec_command` 调用按两种签名重放：

| 编号 | 判据 | 门槛 |
|---|---|---|
| N1 | 归一后「某组达到 K=3」的 run 占比 | **≥ 20%**（否则三连同一命令在本项目罕见，不修） |
| N2 | 首次命中位置占该 run 总调用数的比例，中位 | **≤ 50%**（太晚等于没做） |
| N3 | 解出 run 里被误触发的比例（假阳性护栏） | **≤ 15%** |
| N4 | 归一前命中率（对照） | 记录即可，用于证明修复确实改变了可达性 |

N1–N3 全过 ⇒ 修 + A/B（§5.2 同判据）；任一不过 ⇒ 不修，写进台账。

### 8.4 判决（2026-11-15，零 token 重放）：D 也停

同一批 443 个 `agents.db` / 405 场 / 7,460 次 `exec_command`（344 场有 ≥3 次 exec）：

| 判据 | 门槛 | 实测 | 判决 |
|---|---|---|---|
| N1 归一后 K=3 命中 run 占比 | ≥20% | **0.0%**（0/344） | **不过** |
| N2 首次命中位置中位 | ≤50% | 无命中 | 不可用 |
| N3 解出 run 误触发 | ≤15% | 0/162 | 无样本 |
| N4 归一前命中率（对照） | 记录 | **0.0%**（0/344） | H1 被证伪 |

**H1 为什么错**：99.8% 的输出确实带 `Chunk ID` / `Wall time`，但**同参数调用对里 91/102
本来就是字节相同的**（噪声归一只能再多救 1 对）。噪声不是问题。

**H2 被数据支持**：真正的瓶颈是重复量——344 场里只有 **2 场（0.6%）**出现过同一条命令
≥3 次；这 2 场里三次输出归一后也确实不同。也就是说，模型在命令层面**本来就不重复**，
`negative_guard` 的判据在真实行为分布上几乎无对象。

**处置**：不改签名、不做 A/B。`negative_guard` 保留为「同命令同输出」守卫（它对更慢的
模型/别的供应商仍可能有用），但在我们的正常分布上它不是换向机制。`docs/37` 里
「先查为什么 0」到此结案：原因不是路径断，是判据与行为不匹配。

### 8.5 对「换向问题」的总判决

两条最省事的换向设计（A 状态平段强制换类、D 修同命令守卫）都按预注册前提被证伪，
且失败方向一致：**我们的模型不是「陷在一个方向上反复打」，而是持续换东西打**。
所以「让他换向」这个药方在本项目的历史分布上找不到靶子；如果要提升，方向应该从
「换不换」转为「换到的方向对不对 / 每次拿到的信息够不够」。

下一步候选（按可测前提排序，均未开工）：

1. **事实入必经路径**（docs/37 缺口 #5）：`http_probe` 结果尾部附本页路由/表单/参数。
   可离线量：历史 `http_probe` 输出里的链接有多少后续从未被请求、解出组与失败组是否
   有差异。
2. **生成式枚举的早期事实**：一次调用里出现上百条候选路径时，结果尾部说明「这是一次
   字典扫描、已试 N 条、命中 M 条」——043 一次 3,320 条候选而 `enum_hits=0`。
3. 浏览器 / OOB：镜像与冻结窗口不允许，留到赛后。
