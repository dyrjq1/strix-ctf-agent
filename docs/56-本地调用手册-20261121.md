## 2. 路径 A：本机指挥 VM 跑 strix

### 2.1 通道：`ctf-desk\tools\vm.py`（paramiko，不经过本地 shell）

```powershell
$VM='C:\Users\rjq\ctf-desk\tools\vm.py'
& 'D:\anaconda\python.exe' -I $VM "uname -a"                 # 执行一条命令
& 'D:\anaconda\python.exe' -I $VM --sudo "apt-get install -y gdb"
& 'D:\anaconda\python.exe' -I $VM --put 本地文件 远程路径
& 'D:\anaconda\python.exe' -I $VM --get 远程路径 本地文件
& 'D:\anaconda\python.exe' -I $VM --script 本地.sh           # 上传 + sed CRLF + bash
& 'D:\anaconda\python.exe' -I $VM --timeout 900 "make -j4"
```

- 密码来自 `ctf-desk\secrets.json` 的 `VM_PASS`（或环境变量 `VM_PASS`），**不打印**。
- **不要用 `ssh "...$VAR..."`**：PowerShell 会先展开 `$VAR`（`\$` 不是转义，反引号才是）。
  paramiko 不过本地 shell，这是本机唯一稳的远程通道。
- 长脚本一律本地写 `.sh` → `--script`；`$`、引号、中文都不会被本地吞。

### 2.2 起一条车道（VM 侧脚本已就位）

VM 上现成的入口：`~/work/run_strix_lane.sh`（模型/网关/key 由环境变量给）：

```bash
LANE_MODEL=<模型> LANE_API_BASE=<网关 base> LANE_KEY_NAME=<llm.env 里的键> \
  bash ~/work/run_strix_lane.sh <name> <kind> <target> [题面文件] [附件目录]
```

- `kind` = `web | tcp | file`；`file` 题的 target 可写 `offline`。附件目录可选。
- key 从 `~/secrets/llm.env` 读，`LANE_KEY_NAME` 选键名（如 `BAILIAN_KEY2` / `BAILIAN_KEY3` / `ZHIPU_KEY`）。
- 脚本内部实际是：

  ```
  nohup .venv/bin/python ~/work/strix_nolimit.py <repo>/scripts/run_strix_ctf.py \
        --name <name> --target-kind <kind> --target <target> --turns 200000 \
        --result-out ~/work/STRIX/<name>/result.json ...
  ```
  环境里 `CTFY_WALL_DEADLINE=0`（不限墙钟）、`CTF_IDLE_SECONDS=600`。日志 `~/work/STRIX/<name>/run.log`。
- 从本机发起（一条命令）：

  ```powershell
  & 'D:\anaconda\python.exe' -I 'C:\Users\rjq\ctf-desk\tools\vm.py' `
    "LANE_MODEL=glm-5.3 LANE_API_BASE=https://dashscope.aliyuncs.com/compatible-mode/v1 LANE_KEY_NAME=BAILIAN_KEY2 bash ~/work/run_strix_lane.sh FOO-1 web http://127.0.0.1:8080/ ~/work/ins_foo.txt"
  ```

  目标地址必须是 **VM 能连到**的；内网题先在 VM 起隧道（§2.5）。

### 2.3 看 / 停 / 判活

```powershell
& 'D:\anaconda\python.exe' -I $VM "tail -30 ~/work/STRIX/FOO-1/run.log"
& 'D:\anaconda\python.exe' -I $VM "cat ~/work/STRIX/FOO-1/result.json"
& 'D:\anaconda\python.exe' -I $VM "ps -o pid,etime,cmd -p \$(cat ~/work/STRIX/FOO-1/lane.pid)"
& 'D:\anaconda\python.exe' -I $VM "kill \$(cat ~/work/STRIX/FOO-1/lane.pid)"
```

（带 `$` 的命令若被本地吞，就写成 `.sh` 用 `--script`。）
判活看两样：`lane.pid` 的进程在，且 `run.log` 在长。日志停在 `[llm] endpoint ...` 一行 = 死在启动阶段。

### 2.4 换树（代码同步；当前 VM 树是 2026-11-20 01:07 的快照）

VM 树**不是 git 仓库**；`git archive` 导出的是**仓库内容平铺在根**（没有外层目录名）。

本机侧（未提交改动不会进包，先 commit）：

```powershell
$W='C:\Users\rjq\Downloads\strix-ctf-agent\.claude\worktrees\night-20261113'
$T="$env:TEMP\tree.tar"
git -C $W archive --format=tar --output=$T HEAD
& 'D:\anaconda\python.exe' -I 'C:\Users\rjq\ctf-desk\tools\vm.py' --put $T /tmp/tree.tar
```

VM 侧（写成 `swap.sh` 用 `--script` 发；**先备份，改完自检**）：

```bash
#!/bin/bash
set -euo pipefail
NEW=/tmp/tree-new; DEST=/home/rjq/work/strix-ctf-agent
rm -rf "$NEW"; mkdir -p "$NEW"; tar -xf /tmp/tree.tar -C "$NEW"
test -d "$NEW/src/ctf_strix" || { echo "bad archive"; exit 1; }
BAK="$DEST.bak-$(date +%m%d-%H%M)"
mv "$DEST" "$BAK"; mv "$NEW" "$DEST"; mv "$BAK/.venv" "$DEST/.venv"
PYTHONPATH="$DEST/src:$DEST/vendor/src" "$DEST/.venv/bin/python" \
  -c 'import ctf_strix.limits as l; print("import ok", l.MAX_TURNS, l.MAX_WALLCLOCK_S)'
echo "backup=$BAK"
```

回滚：`mv $DEST $DEST.bad; mv /home/rjq/work/strix-ctf-agent.bak-<时间> $DEST`。

**已实测（2026-11-21）**：本机 HEAD `f2781b5` → 38 MB tar → VM 解包 3441 个文件 →
用现成 `.venv` `import ctf_strix.limits` 成功（`MAX_TURNS=1000000`、`MAX_WALLCLOCK_S=1800`）。
换树本身**未执行**（会动正在用的树），按需执行。

⚠ 只拷改动文件会漏旧文件的改动（本项目出过「嵌合体」事故）；要换就整树换 + manifest 对账。

### 2.5 VPN 在 VM 上

- VM 内核支持 wireguard：`sudo -n ip link add wgtest type wireguard` 实测 OK；`/usr/bin/wg`、
  `wg-quick`、`/usr/local/sbin/ctfvpn-wg`、`/etc/sudoers.d/ctfvpn` 都在。
- sudo 白名单只有 `ip / wg / wg-quick / dig / ctfvpn-wg`；`modprobe` 不在里面（也不需要——用 `ip` 建链）。
- 用法与 `docs/54` 同一套（`ctf_strix.vpn.VpnTunnel`）；VM 树上暂时没有 `scripts/vpn_up.py`，换树后就有了。
- profile 来自平台 `GET /api/v1/instances/{iid}/vpn-config`，**每实例一份**；
  一个 private key 只能挂一个端点——人机不能同时拿同一个 profile。

## 3. 路径 B：本机 `ctfdesk`（claude / codex 车道，人机协同）

### 3.1 目录结构

```
C:\Users\rjq\ctf-desk\
  inbox\<CID>\          meta.json + statement.md + files\
  agents.json           车道定义：命令模板 + env + @secret: 引用
  secrets.json          密钥（VM_PASS / QWEN_KEY_A / BAILIAN_KEY2 / ZHIPU_KEY / XIAOMI_KEY …）
  work\<CID>\<agent>\   每路工作目录（RESULT.json / transcript.md / lane.log）
  outbox\submit-sheet.md  给人看的提交单
  outbox\evidence\      每路的 stdout / RESULT / VERIFY 证据
  outbox\wp\            WP 草稿
  status\               巡检快照
```

### 3.2 加题 / 跑 / 看

```powershell
$py='C:\Users\rjq\Downloads\strix-ctf-agent\.venv\Scripts\python.exe'
$W='C:\Users\rjq\Downloads\strix-ctf-agent\.claude\worktrees\night-20261113'
$desk="$env:USERPROFILE\ctf-desk"

& $py "$W\scripts\ctfdesk.py" add --root $desk --id JHB-WEB-03 --name "题名" `
    --category web --target http://10.0.0.5:8080/ --target-kind web `
    --files .\dl\jhb03 --agents claude,codex

& $py "$W\scripts\ctfdesk.py" watch --root $desk --workers 2 --once   # 排一轮就退
& $py "$W\scripts\ctfdesk.py" status --root $desk
& $py "$W\scripts\ctfdesk.py" record --root $desk --id JHB-WEB-03 `
    --command "curl ..." --observed "flag{...}" --result pass
```

一键开场：`& "$W\scripts\start_desk.ps1"`（无参 = watch 循环，workers=3）。
注意它把 `LLM_API_*` 设成 qianwen 网关，只对没写死 `settings` 的车道有效；claude 三条车道自带 `--settings`。

### 3.3 `inbox\<CID>\meta.json`

```json
{"id":"JHB-WEB-03","name":"题名","category":"web","target":"http://10.0.0.5:8080/",
 "target_kind":"web","flag_format":"flag\\{[^}]+\\}","agents":["claude","codex"]}
```

**`agents` 里不要写 `strix`**——那一路在 Windows 8 秒就死（§1.1）。可选车道：

| agent | 网关 / 模型 | 密钥引用 |
|---|---|---|
| `claude` | qianwen MaaS（Anthropic 口）/ deepseek-v4.1-flash | `@secret:QWEN_KEY_A` |
| `claude-glm` | dashscope（Anthropic 口）/ glm-5.3 | `@secret:BAILIAN_KEY` |
| `claude-mimo` | 小米 MiMo（Anthropic 口）/ mimo-v2.6-pro | `@secret:XIAOMI_KEY` |
| `codex` | qianwen MaaS（Responses 口）/ deepseek-v4.1-flash，40 分钟 | `@secret:QWEN_KEY_B` |

### 3.4 并发与产出

- 并发：先按可用内存收窄——保底 1500 MB，每路按 700 MB 估，`--workers` 只是上限。
- 每路跑完写 `work\<CID>\<agent>\RESULT.json`（`{"flag","confidence","notes"}`）+ `transcript.md`，
  agent 按要求还应写 `VERIFY.md`（复现命令 / 期望输出 / 来源核对）。
- `ctfdesk` 抽 flag → `outbox\flags.jsonl` → `outbox\submit-sheet.md`（conf ≥ 0.9 标「可直接提交」）。
- **平台提交永远由人做**（人机协同规则）；claude 车道用空 MCP + `--strict-mcp-config`，agent 碰不到平台接口。

### 3.5 一个坑：失败的车道会把题卡在 `running`

开跑时题状态置 `running`，只有拿到 flag 且 conf ≥ 0.9 才转 `done`；`watch` 跳过 `running`。
所以车道死掉后题**不会自动重试**。要重试先改回 `pending`：

```powershell
& 'D:\anaconda\python.exe' 'C:\Users\rjq\ctf-desk\tools\requeue.py' --id JHB-WEB-03
```

（`requeue.py` 只是一条 `UPDATE challenges SET status='pending'`；本机 `python -c` 有吞引号风险，别用它。）

## 5. Windows 坑（本项目实测，逐条）

1. 不要 `python -c "..."`：PowerShell 吞引号 → 写 `ctf-desk\tools\xxx.py` 再执行。
2. PowerShell 5.1 的 `Set-Content -Encoding utf8` **加 BOM**；scp 到 Linux 后 bash 报
   `\ufeff#!/bin/bash: No such file or directory`。用 `vm.py --script`（文件无 BOM）或
   `[IO.File]::WriteAllText(... UTF8Encoding($false))`。
3. `ssh "... $VAR ..."` 的 `$VAR` 被本地展开（`\$` 不是转义）；远程命令走 `vm.py`。
4. 控制台 GBK：中文/emoji 会 `UnicodeEncodeError`；`$env:PYTHONIOENCODING='utf-8'` 或先写文件。
5. `pathlib.write_text(..., newline='\n')` 在 Windows **先截断再抛错**；一律临时文件 + `os.replace`。
6. npm 的 claude/codex 是 `.cmd`/`.ps1` 壳：CreateProcess 不认无扩展名，要 `shutil.which`；
   超时用 `taskkill /F /T /PID` 杀整棵树（只杀 cmd 会留下 node 攥着管道）。
7. 只杀自己启动的 PID；禁 `taskkill /IM python.exe`、`Get-Process python | Stop-Process`、`pkill -f python`。
8. `secrets.json` 不要 `cat` / `ConvertFrom-Json` 打屏——解析一出错，整份密钥就回显到终端。

## 7. 红线

1. 密钥只在 `ctf-desk\secrets.json`、`~/secrets/llm.env`、`/root/lanes.conf`；不进 git、不打屏。
2. 真题 flag 不进任何被 git 跟踪的文件（`docs/53` 已脱敏）。
3. 换 VM 树只走「整树替换 + 备份 + import 自检」；不做增量拷贝。
4. 人机协同下平台提交只由人做；agent 不碰平台接口。
5. 网关只用 deepseek / 智谱 / 百炼 / 小米；paratera 禁用。
6. 本机不跑 strix 车道：8 秒死、占内存、还可能写脏 `work\` 目录。
