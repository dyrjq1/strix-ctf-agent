# VPN 接入与隧道操作手册（给人机协同 / 解题 Claude）

> 2026-11-21 · 读者：**没有上下文的新会话**（VPS 上的解题 Claude、或接手的人）
> 适用：`tcp_access=vpn` 的题（服务地址是 `*.internal` 内网名，不连隧道连靶面都看不到）
> 机器：VPS `root@39.107.41.223`，仓库 `/root/deploy/strix-ctf-agent`

## 0. 30 秒速通（照抄即可）

```bash
# ① 有 pk_ token、用 CTFY API 起实例的：直接拉 profile
PK=$(cat /root/.pft)
IID=<实例 id>
mkdir -p /root/vpn && chmod 700 /root/vpn
curl -sS -H "Authorization: Bearer $PK" \
  "https://ctfy.tsinghua.edu.cn/api/v1/instances/$IID/vpn-config" > /root/vpn/$IID.conf
chmod 600 /root/vpn/$IID.conf
grep -c '^\[' /root/vpn/$IID.conf        # 期望 2（[Interface] + [Peer]），0 说明平台没给 profile

# ② 起隧道（profile 来自页面下载的 .conf 时同样用这条）
python3 /root/tools/vpn_up.py up /root/vpn/$IID.conf

# ③ 验证（三条全过才算通）
sudo -n wg show wgctf | grep latest-handshake   # 不是 0
ip -4 route | grep wgctf                         # 有该题网段
dig +short @<上一步打印的 dns> <靶面主机名>      # 出 10.x

# ④ 拆（换题 / 收工必做）
python3 /root/tools/vpn_up.py down
```

## 1. 三条原理（不懂会踩坑）

1. **profile 是按实例生成的**：`/instances/{id}/vpn-config` 每次返回该实例专属的
   私钥、对端公钥、`10.x` 地址、内网 DNS。**不能复用别的实例的**。
2. **一个 peer 只有一个端点**：WireGuard 服务端对同一把公钥只记最后一次握手的来源。
   人和 VPS 同时导入同一份 profile → 两边互相踢，表现为"一会儿通一会儿超时"。
   **一条隧道只能有一个所有者。**
3. **我们不动 `/etc/resolv.conf`**：`wg-quick` 会把 `DNS=` 写进解析器（容器里会失败，
   还会改坏宿主）。我们的脚本只建接口、配地址、加路由；**内网域名要靠
   `dig @<profile 里的 DNS>` 显式问**，或用下面的 `/etc/hosts` 小技巧。

## 2. profile 从哪来

| 场景 | 做法 |
|---|---|
| 实例由 CTFY API 起（我们有 `pk_` token） | §0 的第 ① 步，`curl ... /vpn-config` |
| 实例由**页面**起（DataCon / CTFY 网页），配置可下载 | 把下载到的 `.conf` 传到 VPS：`scp xxx.conf root@39.107.41.223:/root/vpn/<iid>.conf`，再 `chmod 600` |
| 平台只给了一串文本 | 自己存成 `.conf`，格式必须是 wg-quick 的 `[Interface]/[Peer]` |

profile 长这样（**私钥永远不要打印、不要进 git、不要贴聊天**）：

```ini
[Interface]
PrivateKey = <base64>            # 实例专属，一次性
Address = 10.12.34.5/32
DNS = 10.12.0.1                  # 内网解析器

[Peer]
PublicKey = <base64>
AllowedIPs = 10.12.0.0/16        # 这道题可达的网段（可能多条）
Endpoint = node17.tpctf.example:51820
```

判空：`grep -c '^\['` 不是 2，或者文件里有 `error`/`not found` 字样 → **平台没给 profile**，
先别怀疑网络；看 §6 第 1 行。

## 3. 起隧道

脚本：`/root/tools/vpn_up.py`（仓库里是 `scripts/vpn_up.py`，内容一样）

```bash
python3 /root/tools/vpn_up.py up /root/vpn/<iid>.conf
```

成功时打印：

```
[vpn_up] UP  iface=wgctf  addr=10.12.34.5/32
[vpn_up]      routes=10.12.0.0/16
[vpn_up]      dns=10.12.0.1
[vpn_up]      endpoint=node17.tpctf.example:51820
```

它内部做五件事（出问题按这个顺序查）：

1. `ip link del wgctf` —— 清理上一次崩溃留下的同名接口（幂等）
2. `ip link add wgctf type wireguard`
3. `ctfvpn-wg wgctf`，把 `[Interface]/[Peer]` 从 stdin 喂进去 —— **必须走这个包装**，
   直接 `wg setconf` 写临时文件会被 Ubuntu 的 AppArmor 挡成 `fopen: Permission denied`
4. `ip -4 addr add` + `ip link set mtu 1420 up`
5. `ip -4 route replace <AllowedIPs> dev wgctf` —— 用 `replace`，否则旧隧道的路由
   会把新流量黑洞掉（现象：握手成功、内网全超时）

然后等最多 10 秒握手；**握手不成功就拆接口并报错**。

接口名默认 `wgctf`，要并行多条用 `--iface wgA`（**注意 `--iface` 写在子命令前面**）：

```bash
python3 /root/tools/vpn_up.py --iface wgA up /root/vpn/A.conf
```

## 4. 验证（三条，缺一不可）

```bash
sudo -n wg show wgctf | grep -E 'latest-handshake|transfer'
#   latest-handshake 非 0 且 transfer 在涨 = 通

ip -4 route | grep wgctf
#   必须出现 profile 里的 AllowedIPs 网段

dig +short @10.12.0.1 <靶面主机名>
#   出 10.x 地址 = 内网解析也通
```

> 宿主的 `getent hosts <内网名>` **大概率失败**，这是设计如此（我们不碰全局 DNS）。
> 只认 `dig @<profile DNS>`。

## 5. 打题的三姿势

### 5.1 机器上直接打（agent / 命令行）

```bash
# ① 让内网名在这台机器上可解析（一次性，收工删掉）
echo "<dig 出来的 IP> <靶面主机名>" | sudo tee -a /etc/hosts

# ② 之后一切照常
curl -m 10 -i "http://<靶面主机名>:<端口>/"
python3 - <<'PY'
import socket
s = socket.create_connection(("<靶面主机名或IP>", 31337), 10)
s.sendall(b"\n"); print(s.recv(4096)[:200])
PY

# ③ 收工：删掉 hosts 那行
sudo sed -i '/<靶面主机名>/d' /etc/hosts
```

> `/etc/hosts` 只是让**本机**能解析；它不改变隧道，也不影响别人。加之前确认没有同名条目。

### 5.2 人用浏览器（隧道仍在 VPS）

```bash
# 人这边执行（不要导入 wireguard 客户端！）
ssh -D 1080 root@39.107.41.223
# 浏览器 → 代理 → SOCKS5 127.0.0.1:1080 → 勾"远程 DNS"
```

配合 5.1 的 `/etc/hosts` 那行，浏览器输入内网名就能开页面（SNI/Host 都对）。
只要一道口子也行（注意 TLS 的 SNI 会变成 127.0.0.1，web 题更推荐 SOCKS 方式）：

```bash
ssh -L 8080:<靶面IP>:<端口> root@39.107.41.223
```

### 5.3 多台主机的场景

`AllowedIPs` 有多条时，起隧道时每条都加了路由；把第二台主机的名字同样查出来加 hosts 即可。

## 6. 排错表

| 现象 | 判断 | 动作 |
|---|---|---|
| `/vpn-config` 返回空 / 只有 error，`grep -c '^\['` ≠ 2 | **这题不是 vpn 接入**，或平台抖动 | 看实例详情的 `services`/`entry_urls`；5xx 等 1 分钟重取 |
| `[vpn_up] 隧道没起来` + `latest-handshake 0` | 端点/中转问题 | `dig +short <Endpoint 主机名>`；换实例；有中转时设 `CTF_VPN_RELAY=host:port` 再试 |
| `fopen: Permission denied`（dmesg 里 `apparmor="DENIED" profile="wg"`） | 没走 `ctfvpn-wg` 包装 | 确认 `/usr/local/sbin/ctfvpn-wg` 存在；缺了就 `sudo bash scripts/install_vpn_sudoers.sh` |
| `sudo: a password is required` | sudoers 白名单没装 | 同上；**不要**改成交互式 sudo（无人值守会挂死） |
| 握手成功、但内网全部超时 | 旧 `ip route add` 留下的黑洞路由 | `ip -4 route replace <网段> dev wgctf`（脚本已用 replace，手工做时别用 add） |
| `ip link add ... File exists` | 上次崩溃的接口没拆 | `python3 /root/tools/vpn_up.py down` 再 up |
| 页面 404 / 连接被重置但 ping 通 | 端口或 vhost 不对 | 先 `curl -i` 看响应头；再试 `Host:` 头 |
| 平台 429 `Rate limited by upstream API` | 并发配额满（全队 cap 3） | 停掉不用的实例；**不要重试风暴** |
| 人这边"一会儿通一会儿不通" | **同一份 profile 被两处同时用** | 只保留一个所有者：人在 Windows 上 `wg-quick down` |

## 7. 红线（违反会出事）

1. **私钥不进日志、不进 git、不贴聊天**。profile 一律 `chmod 600`；调试打印只打接口名/网段。
2. **一条隧道一个所有者**：人在用，agent 就别起；agent 在用，人就走 SSH。
3. **不改 `/etc/resolv.conf`**，DNS 只显式 `dig @`。
4. **收工必拆**：`python3 /root/tools/vpn_up.py down`；顺手删 `/etc/hosts` 里加的那行。
5. 隧道只对**本实例网段**加路由；不要写 `0.0.0.0/0`，会把 VPS 自己的出网也带进隧道。
6. 平台查询走 MCP / 官方 API，token 只从 `/root/.pft` 读，**不要打印**。
