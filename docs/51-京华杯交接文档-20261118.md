## 3. 能用什么、不能用什么

### 3.1 可原样复用（与平台无关）

- **agent 内核与工具面**：`src/ctf_strix/`（web 四原语、流量台账、CVE 离线库、附件/tcp 工具、13 个技能索引）——这是最值钱的部分，换平台也照用。
- **部署包与冷启动**：`bootstrap.sh`（解包 → venv 重指向 → import 自检）、`debs/`、`sqlmap/`、`py/`。
- **运行环境配方**：`PATH` / `LD_LIBRARY_PATH` / `LITELLM_LOCAL_MODEL_COST_MAP` / `LLM_MAX_TOKENS=8192`（§11 命令卡）。
- **车道模型**：多厂商分工 + `lanes.conf` 隔离，与比赛平台无关，只跟网关有关。
- **VPN/接入层**：`ctf_strix.vpn` + `install_vpn_sudoers.sh`（只要平台还是 WireGuard 接入）。

### 3.2 需要改才能用（平台适配）

| 资产 | 依赖什么 | 换平台时的动作 |
|---|---|---|
| `scripts/compete.py` | CTFY MCP（`list_competition_challenges` / `start_instance` / `submit_answer`） | 非 CTFY 平台：不要改它，改跑 `run_strix_ctf.py` 单题；或在 T-1 天写 20 行适配器把「取题→起实例→提交」换成新平台 API |
| `scripts/batch_eval.py` | CTFY 实例 API + `plan.json` | 同上 |
| `experiments/pools.json` | 留出集，**不许碰**（CLAUDE.md §7.3） | 保持原样 |
| 题池档位（small/medium/large 自动调参） | 靠「未关闭题数」判档 | 新平台没有这个字段时，`CTF_REGIME=off` 固定 medium |
| 提交链路 `autosubmit.py` | 平台答案校验接口 | 必须先单题验一次「提交-判分-回显」闭环，再信它 |

### 3.3 人机协同的两种运行档

规则没吃透之前，按**保守档**跑；等 §2 的 Q2/Q3/Q4 有明确答案，再决定要不要切放开档。

**保守档（= 纯 agent 赛道行为，任何规则下都合规）**

| 人类可做 | 人类不可做 |
|---|---|
| 看状态、看日志、起停实例、报故障、调车道并发 | 看题面后给 agent 提示/题解/代码 |
| 判断「agent 是不是卡死了」并重启 | 手工提交 flag、手工挑题 |
| 与主办方沟通 | 改 agent 的提示词或工具 |

**放开档（仅当规则明文允许人机交互）**

| 人类可做 | 判据 |
|---|---|
| 自己读题面，把**题面原文**（不是解法）整理给 agent | 规则说「人类是选手」即允许 |
| 把侦察结果（端口/目录/报错）转告 agent，共同决策 | 人类本来就能自己看 |
| 人类亲自上靶机做题，agent 做辅助/批处理 | 规则没禁止「人类提交」 |
| 赛中改 agent 的脚本/提示/工具 | 规则说「可中途调试」才允许；TPCTF 明令禁止 |

⚠️ 即使放开档，下面两条**永远不破**：真实 flag 不进任何被 git 跟踪的文件；凭据不进日志、不进 argv。

## 6. 人机协同的分工与沟通协议

### 6.1 分工

| | 人 | agent |
|---|---|---|
| 合规 | ✅ 判规则、判这条线能不能碰 | 按人的裁决执行 |
| 平台 | ✅ 建会话、报故障、联系主办方 | 起停实例、提交 |
| 战略 | ✅ 定优先级、定时盒、决定放弃哪题 | 提供数据支撑决策 |
| 执行 | 放开档下可亲手做题 | ✅ 批量侦察、写脚本、跑利用链、记录台账 |
| 记录 | 看一眼结果 | ✅ 全程落盘（日志/results/agents.db） |

### 6.2 交接给 agent 的正确姿势

**给现象，不给结论。** 同一件事，两种说法差别很大：

| ❌ 不要这样 | ✅ 要这样 |
|---|---|
| 「这题是 SQL 注入，跑 sqlmap」 | 「登录页提交 `admin'--` 后返回 500，正常登录返回 302。目标 `http://x/`。你怎么看？」 |
| 「flag 在 /flag.txt」 | 「读 `/flag.txt` 返回 `Permission denied`，当前用户 `www-data`」 |
| 「卡住了，换个思路」 | 「最近 6 次调用都是同一个 404，工具是 `http_probe`，日志第 30–42 行」 |

理由：给结论等于让人替 agent 做判断（保守档违规、放开档也没必要）；给现象 agent 才在用它自己的工具面。

### 6.3 agent 回给人的正确姿势

要求 agent 输出的每一条可执行结论都带**一条可复制的命令**和一个**判据**，例如：

```bash
tail -50 ~/compete.log | grep -E 'lane|fail|defer'    # 判据：有本分钟的时间戳
```

人不需要懂细节就能判断「它还在不在干活」。

### 6.4 时间盒

- 单题 **15 分钟**无进展 → 记录后换题（agent 侧 `--wallclock 300` 是 easy 档基数，medium/hard 自动放大）。
- 连续 **3 题**同一种失败（不是同一条报错，是同一类）→ 停止派单，回到 §2 判断是不是接入/规则问题。
- 距收工 **90 分钟** → 不再开新题，只收尾、保全日志。

## 7. 故障速查（按「现象」查）

| 现象 | 最可能 | 处置 |
|---|---|---|
| 所有车道 401/403 | 会话过期 | 重建会话 → 重写 `lanes.conf` → 复验 |
| 400 提到 `max_tokens` | 网关要显式参数 | 确认 `LLM_MAX_TOKENS=8192` 在子进程 env 里 |
| 429 / `Rate limited by upstream API` | 并发超配额 | 降 `--lanes`，**不要**重试风暴 |
| 请求卡 60–75s 后 `Recv failure` | 钉到坏的 Cloudflare 边缘 | `pick_gateway_ip.sh` 重选 → 复跑 preflight；偶发一两次不用管（agent 侧 5 次重试兜底） |
| `getent hosts` 空 / NXDOMAIN | 内网 DNS 劫持 | 重跑 `setup_lanes.sh`（它每次都重钉） |
| `gdb/nmap/rg: command not found` | 启动 shell 没带 bundle PATH | §11 命令 0 的三行 export；`compete.py` 日志首行有「bundle 工具已挂进 PATH」即已生效 |
| `LIBSYSTEMD_* not found` | 用了旧 `bootstrap.sh` | 换 11-18 之后的版本（宿主 lib 目录前置） |
| 队列空 / 车道空转 | 题被 defer | 看 `compete.log` 的 defer 理由；solves 涨 3 会回捞 |
| `SKIPPED(需隧道)` 连片 | VPN 链路 | 依 50 §5 三种结局表：先换实例，再试 `tls_sni` 直连，仍不通报障 |
| 平台 503 / 实例起不来 | 平台侧 | 降并发 + 等 5 分钟 + `report_instance_issue` |

**判断「是不是机器的问题」最快的办法**：跑 `vps_preflight.sh`。它 30+ 项，哪项红就是哪项，
末行 `PREFLIGHT_RESULT_OK|FAIL`。别靠猜。

## 8. 红线（人机协同版）

**永远不变**

1. 真实 flag 不进任何被 git 跟踪的文件；截图/日志同理。
2. 凭据只放机器上的 600 文件或会话 env，不进 git、不进日志、不进 `argv`、不打印明文。
3. 只用四家官方厂商的**平台网关**（`*.llm-next.ctfy.io` + `pk_`）；不直连厂商域名当比赛通道，不走中转站。
4. 不碰 `vendor/`、不碰 `experiments/pools.json`。
5. 不伪造提交、不对着单题失败日志写死字符串（防过拟合四条见 CLAUDE.md §7.3）。

**随规则变（必须先有 §2 的答案）**

6. 人能不能看题面 / 喂题面给 agent（Q2）。
7. 人能不能亲自提交 flag（Q3）。
8. 赛中能不能改 agent（Q4）。
9. 人能不能上网查资料（Q7）。

> 拿不准的时候按保守档跑。保守档不会因为「太保守」被判违规；放开档搞错方向会。

## 11. 命令卡（可整段复制）

```bash
# 0) 每次开新 shell 都要（少了第一行 agent 找不到 gdb/nmap；少了第二行二进制找不到自带库）
cd ~/deploy/strix-ctf-agent
export DEPLOY=~/deploy
export PATH="$DEPLOY/tools/usr/bin:$DEPLOY/tools/usr/sbin:$PATH"
export LD_LIBRARY_PATH="/lib/x86_64-linux-gnu:/usr/lib/x86_64-linux-gnu:$DEPLOY/tools/usr/lib/x86_64-linux-gnu:$DEPLOY/tools/lib/x86_64-linux-gnu${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
export PYTHONPATH=$PWD/src:$PWD/vendor/src
export STRIX_RUNTIME_BACKEND=local LITELLM_LOCAL_MODEL_COST_MAP=True STRIX_TELEMETRY=false
export LLM_MAX_TOKENS=8192
export PF_TOKEN=<平台 token>            # 只在会话里，不写文件
command -v rg && command -v gdb && command -v nmap    # 三条都要有输出
```

```bash
# 1) 装车道（凭据已写进 ~/lane_specs.txt，一行一家 名字|base|pk_[|模型]）
bash deploy/setup_lanes.sh ~/lane_specs.txt --out ~/lanes.conf --verify
# 期望：每家 PICK_OK + model=xxx → SETUP_LANES_OK → 每家 lane probe HTTP 200

# 2) 预检闸门（fail≠0 不许开跑）
bash vps_preflight.sh --deploy ~/deploy --bundle ~/vps-bundle --lanes-conf ~/lanes.conf

# 3) 只看队列，不派单
.venv/bin/python scripts/compete.py --token "$PF_TOKEN" --competition <CID> \
  --state-dir ~/compete-state --lanes 3 --lane-config ~/lanes.conf --dry-run

# 4) 正式开跑
nohup .venv/bin/python scripts/compete.py --token "$PF_TOKEN" --competition <CID> \
  --state-dir ~/compete-state --lanes 3 --lane-config ~/lanes.conf \
  --turns 25 --wallclock 300 --until "<YYYY-MM-DDTHH:MM+08:00>" \
  > ~/compete.log 2>&1 &

# 5) 监控（每 10 分钟一眼）
tail -50 ~/compete.log
wc -l ~/deploy/strix-ctf-agent/strix_runs/*/results*.jsonl 2>/dev/null | tail -3
ls -lt ~/deploy/strix-ctf-agent/strix_runs | head
```

## 12. 交接时最该记住的三句

1. **机器已经好了**——不要因为「京华杯是新的」就重装、重改代码。
2. **规则没吃透就按保守档**——保守档在任何规则下都合规，放开档搞错方向才致命。
3. **人只做两件事**（建会话、交凭据）；其余交给 agent，人负责看结果和判合规。
