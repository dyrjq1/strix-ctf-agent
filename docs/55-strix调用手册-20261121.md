## 0. 三条命令速查

| 想干什么 | 用哪个 | 一句话 |
|---|---|---|
| 跑**一道**题，全自动（起实例→隧道→跑 agent→提交→归档） | `batch_eval.py` | 写一行 plan.json，最省事 |

## 1. 前置（一次性，每个 shell 都要）

```bash
cd /root/deploy/strix-ctf-agent
export PF_TOKEN="$(cat /root/.pft)"        # 平台 pk_ token，600 文件，别打印
export STRIX_RUNTIME_BACKEND=local
export LITELLM_LOCAL_MODEL_COST_MAP=True   # 否则 litellm 联网取价目表会卡
export STRIX_TELEMETRY=false
export LLM_MAX_TOKENS=8192                 # 网关缺参会报误导性 400
```

- **Python 用 `$APP/.venv/bin/python`**（软链到 `/root/deploy/python/bin/python3.14`）。
- `compete.py` / `batch_eval.py` 自己会处理 `sys.path` 和子进程的 `PYTHONPATH`；
  **唯独 `run_strix_ctf.py` 需要手工 `PYTHONPATH=src:vendor/src`**。
- 模型三件套（不走 `--lane-config` 时必须给）：`LLM_API_BASE` / `LLM_API_KEY` /
  `STRIX_LLM=openai/<模型名>`。模型名见 `~/lanes.conf` 第 4 列。

## 2. 单题全自动：`batch_eval.py`（首选）

它会替你做完：**起实例 → 拉 `/vpn-config` 起隧道 → 跑 agent → 内提交 flag → 删实例 → 归档**。

### 2.1 写计划（一行一题）

```bash
cat > /root/plan-one.json <<'JSON'
[{"id": "AUTHORED-3AFA4F62", "difficulty": "medium"}]
JSON
```

字段：`id`（必填）、`difficulty`（必填，`easy|medium|hard`，决定预算放大：
medium ×1.6 轮/×1.5 墙、hard ×2.4/×2.3，再被 `limits` 夹住）、`model`（可选，覆盖默认模型）。

### 2.2 跑

```bash
cd /root/deploy/strix-ctf-agent
.venv/bin/python scripts/batch_eval.py \
  --plan /root/plan-one.json \
  --token "$PF_TOKEN" \
  --competition-id <比赛 cid> \
  --out /root/results-one.jsonl \
  --archive-dir /root/runs \
  --turns 25 --wallclock 300
```

常用参数：

| 参数 | 说明 |
|---|---|
| `--competition-id` | 正式赛必给（也可 `CTFY_COMPETITION_ID` 环境变量）；练习场可不给 |
| `--turns` / `--wallclock` | 单题**基准**（easy 档），medium/hard 按上表放大，最后 clamp 到 1800s |
| `--max-turns` / `--max-wallclock` | 所有难度共用的**硬上限**；0 = 只按难度分层 |
| `--max-samples N` | 每题最多跑几次；>1 时只在"无进展"收场后换策略重开（solved/wallclock 不重开） |
| `--no-hints` | 关掉平台 hint 的只读探测（默认开，只取已释放且免费的） |
| `--no-archive` | 不归档（**只有冒烟时用**，会丢事后回放能力） |

### 2.3 看结果

```bash
tail -f /root/results-one.jsonl     # 每完成一题追加一行
```

每行关键字段：`correct`、`agent_s`、`tool_calls`、`usage`（`llm_calls/input_tokens/output_tokens`）、
`stop_reason`（`wallclock` / `no_progress` / `unknown`…）、`run_id`。

## 3. 单题手动靶面：`run_strix_ctf.py`

**它不起实例、不建隧道、不提交**（除非给 `--autosubmit`）。靶面已经是你能连的状态时用它。

```bash
cd /root/deploy/strix-ctf-agent
PYTHONPATH=src:vendor/src .venv/bin/python scripts/run_strix_ctf.py \
  --target http://<靶面主机>:<端口>/ \
  --target-kind web \
  --turns 40 \
  --tags web nginx php \
  --name manual-3AFA4F62
```

| 参数 | 什么时候用 |
|---|---|
| `--target-kind` | `web`（URL）/ `tcp`（`host:port`）/ `file`（纯附件，无网络） |
| `--files-dir DIR` | 附件题：把目录内容拷进 agent 工作区，它不用自己去下载 |
| `--tags ...` | 平台发布的标签；决定挂哪些 AI 安全工具、注入哪些方法卡（不含题号/路径） |
| `--instruction "..."` | 追加一句任务说明（会进根任务） |
| `--soft-deadline S` | 到点后提示 agent 收敛（不杀进程） |
| `--wall-deadline S` | 只用于措辞和解除停滞抑制；**真正杀进程的是父进程** |
| `--autosubmit --platform https://ctfy.tsinghua.edu.cn --instance <iid>` | 让 `finish_scan` 当场把 flag 交上去 |
| `--result-out PATH` | 硬看门狗兜底 result.json 的落点（不放它会分不清"被杀"和"崩溃"） |

附件/内网场景的顺序：**先按 `/root/VPN-RUNBOOK.md` 起隧道 → 再跑本命令**。
`--target` 填内网名或 dig 出来的 IP 都行（隧道里那个网段才通）。

## 4. 整场：`compete.py`

```bash
cd /root/deploy/strix-ctf-agent
nohup .venv/bin/python scripts/compete.py \
  --token "$PF_TOKEN" \
  --competition <cid> \
  --state-dir /root/compete-state \
  --lanes 3 \
  --lane-config /root/lanes.conf \
  --turns 1000000 --wallclock 1800 \
  --until '2026-11-22T20:00:00+08:00' \
  >> /root/compete.log 2>&1 &
```

- **先 `--dry-run` 看队列**，再正式跑；`--once` = 排一轮就退出（冒烟用）。
- `~/lanes.conf` 格式：`厂商名|LLM_API_BASE|pk_…|模型名`，一行一条，`chmod 600`。
  当前三行：`deepseek|…|deepseek-flash`、`bailian|…|qwen4-max`、`zhipu|…|glm-5.3-flashx`。
  **`--lanes N` 取前 N 行；`--lanes > 1` 时一家厂商只能一条车道**，重复 base/模型会 rc=2 拒启。
- 派单是**波次**的：三条车道等最慢那条收车才开下一波——单题墙钟设太大，先收车的车道会空转。
- 关键开关：`--lane-stagger 30`（相邻车道错峰起跑）、`--race-first N`（先解先停，默认关）、
  `--allow-pools`（**正式赛禁用**）、`--ignore-platform-solves`（练习场重跑用）。
- 日志：`/root/compete.log`；状态：`--state-dir`（`state.json`、`runs/*.jsonl`、`digest.md`）。

## 5. 官方镜像入口（平台跑镜像时）

`src/ctf_strix/agent.py` 是比赛镜像的入口：读 `/workspace/task.json` → 跑 → 写 `result.json`。
本地调试/预检用 `$APP/scripts/deploy/agent_run.sh --check`（只读 `~/.ctfy/agent.env` 做环境预检，
缺哪个变量会直接列出来）。

`task.json` 里通常给 `max_turns`、目标地址、附件路径；**运行时以 task.json 为准**，
不要假设 60 轮。

## 6. 产物都在哪

| 内容 | 路径 |
|---|---|
| 每题结果行 | `--out` 指定的 jsonl（compete 用 `state-dir/runs/<challenge>.jsonl`） |
| run 归档（run.log + agents.db） | `--archive-dir`（默认 `~/runs/<run_id>/strix_runs/<run_id>/.state/agents.db`） |
| agent 完整对话 | `agents.db` 的 `agent_messages` 表（JSON items 流） |
| 沙箱附件/提交/用量 | `/var/tmp/ctfbox/<run_id>/`（`attachments/`、`submit.json`、`usage.json`） |

## 7. 常见故障 → 处置

| 现象 | 原因 | 处置 |
|---|---|---|
| `stop_reason=wallclock`，工具调用停在读源码 | 预算不够（编译/打桩类题） | 抬 `--wallclock` 基准；注意上限 1800s |
| `no_progress` / 停滞守卫提前收 | 同一假设反复重试 | 换 `--turns` 无用；换模型车道或换题 |
| `flags` 一直没交上去 | 实例已销毁 / 非 flag 链路 | 看 `/var/tmp/ctfbox/<run>/submit.json`；确认 `--instance` |
| 429 `Rate limited by upstream API` | 平台并发配额（cap 3）满 | 停掉不用实例；**别重试风暴** |
| LLM 400 提到 `max_tokens` | 网关要求显式参数 | 确认 `LLM_MAX_TOKENS=8192` 在子进程 env 里 |
| `exec_command` 里找不到 `gdb/nmap/rg` | bundle 工具的 PATH 没进启动 shell | 看日志首行「bundle 工具已挂进 PATH」；没有就按 docs/50 §4 补两行 export |
| 内网题全部超时 | VPN 没起 / 起错 | 按 `/root/VPN-RUNBOOK.md` 验三条 |

## 8. 红线

1. **凭证只从 `/root/.pft`、`/root/lanes.conf` 读**，不打印明文、不进 git。
2. **正式赛不给 `--allow-pools`、不给 `--ignore-platform-solves`**。
3. 单题墙钟 > 1800s 无效（`limits.py` 夹死）；要改先改代码再重启，改完用
   `PYTHONPATH=src python3 -c 'from ctf_strix.limits import clamp_wallclock; print(clamp_wallclock(9999))'` 验。
4. 跑完记得确认没有残留实例（`compete.py` 会按所有权回收；手工跑的要自己 `stop_instance`）。
5. 单题手动跑（§3）**不会自动交 flag**，除非带 `--autosubmit`；人机协同下也可以由人在答题页交。
