# 镜像怎么到平台手上：三条路，优先级很明确

> 结论先说：**不用 GitHub。平台自己带镜像仓库，用你的 ctfy token 就能 push。**
> GitHub 那条路留着当兜底，配置已经写好了。

---

## 一、平台自带 registry（首选）

平台前端有个组件 `RegistryPushHelp`（从 `ctfy.tsinghua.edu.cn/assets/RegistryPushHelp-*.js`
里读出来的），展开后给的命令是这三行：

```
docker login registry.ctfy.io -u 任意用户名 -p <ctfy token>
docker tag my-agent:latest registry.ctfy.io/f0aef9e3-3b15-4648-8b7c-e1e3c1a01f79/my-agent:v1
docker push registry.ctfy.io/f0aef9e3-3b15-4648-8b7c-e1e3c1a01f79/my-agent:v1
```

`host` = `registry.ctfy.io`（解析到 202.112.238.87，`/v2/` 返 401 +
`www-authenticate: Bearer realm=.../api/v1/registry/token`，是标准 Docker Registry v2）。
命名空间 `f0aef9e3-3b15-4648-8b7c-e1e3c1a01f79` 是账号专属的，别人推不进去。
（⚠️ 早期版本这里写成 `0faaf9e3-...`，是从截图里误读的，权威值以 `/api/v1/me` 返回为准。）

三个关键点：

| 点 | 含义 |
|---|---|
| **密码是 ctfy token** | 不用另建仓库账号，用户名随便填一个就行 |
| **`repository_prefix` 由平台下发** | 每个参赛者的命名空间不同，别自己拼 |
| **镜像落在平台自己家** | 平台拉自己的仓库，不存在「清华拉 ghcr 超时」这回事 |

这也解释了 harness 表单为什么只有一个 `image` 输入框、没有用户名密码字段——
它根本不需要凭据，因为镜像就在它自己的 registry 里。

⚠️ 这个功能受配置开关控制（组件里是 `push?.enabled` 判断），
所以第一步是**去平台设置页看一眼有没有「推送镜像」那一栏**。有就走这条。

## 二、GitHub ghcr（兜底，已就绪）

如果上面那条没开，就只能用外部 registry。已经准备好的东西：

- `.github/workflows/build-image.yml`：构建 amd64 镜像 → 推 ghcr → 跑两项 conformance 自检
- `scripts/publish_ghcr.sh`：建仓库、推代码、触发构建、轮询结果，一条命令

```bash
GH_TOKEN=ghp_xxx OWNER=你的用户名 ./scripts/publish_ghcr.sh
```

两个必须知道的坑：

1. **包必须 public**。harness 表单没有凭据字段，平台是匿名拉取，私有包必然拉不动。
2. **886MB 从清华拉 ghcr 是赌博**。握手能通不代表能拉完，平台侧大概率有超时。

## 三、本地构建（已完成，两条路都用得上）

```
strix-ctf-agent:1.0.0   886MB   amd64   user=agent
```

构建参数（国内必须加，否则 apt 索引能下十分钟）：

```bash
docker build -f docker/Dockerfile \
  --build-arg APT_MIRROR=mirrors.tuna.tsinghua.edu.cn \
  --build-arg PIP_INDEX_URL=https://mirrors.aliyun.com/pypi/simple/ \
  -t strix-ctf-agent:1.0.0 .
```

### 两项 conformance 自检（已通过）

| 场景 | 期望 | 实测 |
|---|---|---|
| 没有 `task.json` | 仍然写出 `result.json` | ✅ `stop_reason=no_target`，269 字节 |
| `dry_run` + `result.path=out/result.json` | 写到指定路径，`stop_reason=dry_run` | ✅ 185 字节，`schema_version=2` |

这两条正好覆盖平台的两个 blocking 判据：`did_not_start` 和 `no_result_file`。

## 四、还差什么

| 需要 | 从哪拿 |
|---|---|
| `host` + `repository_prefix` | 平台设置页「推送镜像」折叠项 |
| ctfy token | 就是跑评测用的那个 |

拿到之后 `docker login` → `tag` → `push`，最后在 harness 表单里填
`<repository_prefix>/strix-ctf-agent:1.0.0`，等管理员审核。
