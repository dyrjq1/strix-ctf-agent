## 3. Bug 1: soft-deadline teardown deadlock (fixed)

`DeadlineGuard.snapshot()` called `should_kill()` while holding `self._lock`,
and `should_kill()` takes the same non-reentrant lock. Every run with
`--soft-deadline > 0` hung at teardown until SIGKILLed.

Consequences: solved challenges were recorded as wall-clock timeouts; the
074/GLM timing was inflated from 62s to 600s, which produced the bogus
"15x slower" claim.

Fix: compute state under the lock, release, then call `should_kill()`.
Regression test `tests/test_deadline_snapshot.py` includes a **counter-example**
that reinstalls the old implementation and asserts it deadlocks within 1s, so
the test cannot silently pass if the bug returns.

## 4. Bug 2: `function_tool(timeout=...)` requires async (fixed)

`agents.function_tool(timeout=180)` silently rejects synchronous handlers with
a `ValueError`. `variants.register()` passed a sync function, so the capability
installer recorded `variants: []` and `path_variants` **was missing from the
tool surface entirely**. It looked exactly like "the model does not know how to
use it".

Fix: blocking work moved to `asyncio.to_thread`, `async def path_variants` is
the thin wrapper. Verified: `installed={'http_probe': [...], 'discovery':
[...], 'variants': ['path_variants']}, errors=[]`.

Lesson for future primitives: **a capability that registers zero tools must be
treated as a failure, not as "not needed this challenge".**

## 5. New primitive: `path_variants`

`src/ctf_strix/variants.py` (+ `docs/18-path-variants.md`, `tests/test_variants.py`)

Turns "remember to try another spelling of this path" into one call. Nine
variant classes (`upper/lower/title/pct/pct2/dot/semi/slash/query`), GET by
default, max 120 requests, concurrency 6, built-in baseline comparison.

Why it works: on 095 both DeepSeek runs locked onto one hypothesis (percent
decoding, then raw sockets) and never tried `/INTERNAL/banner`, while nginx
matched the deny rule case-sensitively and Express routed case-insensitively.
That is six independent bypass mechanisms the model had to *remember* to try.

End-to-end proof (round 3, `20261031-143426`):

```
load_skill -> http_probe -> load_skill -> route_map
-> method_sweep -> path_variants -> http_probe -> finish_scan     (8 calls, 35.9s)

[path_variants] 200 GET [upper] /INTERNAL/BANNER | 57B | ... FLAG{...}
                403 GET [as-is] /internal/banner
```

First time in this project that a flag's provenance is `path_variants` rather
than a hand-rolled `exec_command` curl loop.

## 6. Third bug (small): attempt digest mis-parsed `path_variants`

`attempt_digest._target_of()` preferred `base_url` over `paths`/`urls`, so a
`path_variants` call showed up in the retry digest as `GET t/` -- the paths that
were probed vanished, which is the one thing the digest exists to preserve.
Also `path_variants` was not in the `method_of` GET list, so it was classified
`CMD`.

Fixed, with a regression test
(`test_path_variants_urls_string_is_parsed_not_treated_as_shell`).

## 16. Two traps that cost the most time tonight

1. **"The model is slow" is usually a measurement bug.** Three independent
   signals were needed to prove it: `[done]` and `WALLCLOCK TIMEOUT` in the same
   log, a missing `[deadline]` line, and `usage.json` mtime 6 minutes older than
   `run.log`. Any one alone looks like noise. Check the harness before blaming
   the model.
2. **A capability that registers zero tools is a failure, not a no-op.** The
   async/sync mismatch in `function_tool` produced `variants: []` with no
   exception in the run log, and the symptom was indistinguishable from "the
   model chose not to use the tool". Always assert on the installed tool list.
