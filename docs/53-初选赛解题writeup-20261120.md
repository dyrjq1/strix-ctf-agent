## 1. Mental Card Game —— 二次型哈希不是承诺

### 题面
20 张牌的心理扑克：我是 banker(P0)，服务端跑 P1/P2。附件给了 `chall.py`（服务端）和
`client.py`（参考客户端）。要"每一轮都赢"才给 secret。

### 协议骨架（读 chall.py 得出）
1. P0 提交 20 个整数当牌 → 服务端把它做**三方加法分享**（mod 2^64），
   `x = x0+x1+x2`，P0 拿到 (x0,x1)，P1 拿 (x2,x0)，P2 拿 (x1,x2)。
2. 再生成一组随机标签 `R`，同样三方分享。
3. 做"遗忘洗牌"：给 P0 一个置换 π 和两串 mask，让 P0 交出洗牌后的分享分片。
4. **校验**：服务端用洗牌前后两组值各算一次
   `H(X,R) = Σ (X_i + R_i)·R_i mod 2^64`，相等才算洗牌合法，然后判胜负。

### 突破口
`H` 是二次型。P0 能同时控制两处偏移：牌值偏移 `d`、随机标签偏移 `e`
（`X' = X + d`，`R' = R + e`）。把差分展开：

```
Δ = Σ [ d_i·R_i + e_i·X_i + 2·e_i·R_i + d_i·e_i + e_i² ]
```

所有含**未知量 R** 的项，系数都是 `(d_i + 2·e_i)`。取

```
d_i = -2·e_i
```

未知项整片消失，只剩已知量：

```
Δ = Σ (e_i·X_i − e_i²)   mod 2^64
```

再把 20 张牌全设成同一个常数 `X_i = 13`，并选

```
e_0 = 19·2^32,  e_i = −2^32 (i≥1)
```

于是 `Σ e_i = 0`、每个 `e_i²` 都是 `2^64` 的整数倍 ⇒ `Δ ≡ 0`，校验恒过。
而洗牌后真正的牌是 `13 − 2·e_i`：前 19 张 `8589934605`，最后一张 `1.8×10^19`，
全都远大于合法牌面 52 —— 胜负判定直接倒向"赢"。

要点：**服务端只比较一个低次摘要，而摘要的两个输入都是攻击者给的**，所以摘要能被
"免费"造假；真正该绑的是分片本身（逐分享承诺 / MAC）。

### 落地过程
- 一开始想用 subprocess + pty 本地复现，反复卡在 pty 的 `\r\n` 和提示符匹配上（浪费了约 3 分钟）；
  换成 **`exec(compile(chall.py))` 在进程内跑 + 伪造 `builtins.input()`**，一次就拿到 `You win!`。
- 远端第一次失败：等待字符串写错（提示符里 `'` 的位置），修掉后单连接一次成功。

## 2. Insecure3PC —— 与其篡改输出，不如把输入算出来

### 题面
"作为 P0 参与三方计算，并通过服务器的 challenge 获取 flag"。附件：`README.txt`、
`connect.py`（桥）、`ctf.mpc`、以及一份**改过的 MP-SPDZ 源码包**。

### 结构
- 一个 TCP 入口，按 **1 字节 selector 多路复用**：`0/1/2` 分别对应 P0/P1/P2 的协调，
  `c` 是 AES 挑战面。
- 服务端跑 `ctf.mpc`：`product = (a*b)*c` over `Z_{2^64}`，结果只 reveal 给 P1。
  P1 若拿到非零 product 就拿它当 **AES-128 密钥**；若计算中止（abort）则回落到
  P1 自己的 21-bit 输入当密钥；结果为 0 则直接删密钥。
- AES 侧给你一个挑战块，用对密钥解密出来的**十进制整数**就是答案。

### 走过的三条路（前两条都被堵死，这就是本题吃时间的原因）
1. **篡改输出**：改 `Beaver::finalize_mul` 里第二个三元组的结果分片，可以让 reveal
   出来的是任意值，协议也跑得完 —— 但服务端 judge 自己重算 `a·b·c` 对比，
   直接回 `No Cheating`。此路封死。
2. **伪造 triple**：sacrifice 检查用的随机数 `t` 是**公开**的，给 `c` 加 δ、给 `c'` 加 δ·t
   就能让"错的乘法"通过检查。仍然过不了 judge 的真值比对，判 Informational，没用。
3. **偷看输入（正解）**：replicated 3 方分享里，任何一个 party 都持有两片；
   **P0 和 P2 都跑在自己手里**，两片一拼，P1 的私有输入 `b` 就等于明文了。

### 利用链
1. 找活入口：README 写的 `12000` 协调端口是**陈旧的**（协调服每次都超时死掉），
   真正在服务的是 `172.16.88.2:31337`；`1337` 是 AES 面。
2. 本地用源码包 `-DINSECURE` 编译一个恶意 P0 和 P2（`compile.py -R 64 ctf`）。
3. 在输入 finalize 处打桩，把两片原始分片 hex dump 出来：
   `b = (b − r1) + r1`，实测 `b = 0xa856e`（满足 `b < 2^21` 的结构约束，说明重建正确）。
4. `key = a·b·c mod 2^64`（`a`、`c` 是我们自选的值），取 16 字节大端当 AES-128-ECB 密钥，
   解密挑战块得到十进制明文。
5. **关键时序**：AES 侧连接一旦断开而没作答，P1 会删掉密钥。所以"跑 MPC → 解密 →
   提交"必须在同一条连接里一口气完成。

### 成本观察（对 scheduler 有意义）
同一题在 900s 预算下跑了 6 次，**6 次全部 `wallclock` 收场**（最长 879–906s），
一次都没摸到"编译通过 + 打出 key"的阶段。换成 5400s 的那一次，5048s 解出。
这类"要自己打补丁重编译 MP-SPDZ"的题，900s 只够读源码。

## 3. 在线模型微调 —— 四道门全是纸做的，最后一道是 pickle

### 题面
清华"在线模型微调"服务：把你的模型交上去，它会帮你微调；把服务里的秘密拿出来。
（web / medium，全站 64 队解出）

### 四道门，四张纸
1. **来源 IP 门禁**："仅校内"。发一个 `X-Real-IP: 166.111.1.1` 就过 —— 服务端信了这个头。
2. **浏览器 UA 门禁**：要求精确匹配 `User-Agent: Tsinghua Browser`，照抄即过。
3. **隐藏路由**：首页有一段 base64 注释，解出来是"打开 console 再刷新一次"；照做，
   `/hint.js` 给出隐藏上传端点 `/m0del`（还要求同源 Referer，同样可以伪造）。
4. **文件类型门禁**：`/m0del` 收一个"模型文件"并 `pickle.loads`。

**客户端给的一切（IP 头、UA、Referer）都不能当权限用** —— 这题把四样凑齐了。

### picklescan 绕过
先按常规 `__reduce__ → os.system` 打，被 picklescan 拦下。绕过思路是只用**扫描器白名单
里存在的 global** 拼出执行能力：`operator.attrgetter / itemgetter` 取属性，
`builtins.globals` / `builtins.vars` 拿运行环境，逐层组合摸到 `eval` 这类执行原语，
整条链没有一个"被标红的名字"，扫描器全程放行。

agent 中途踩了两个真坑，都靠"换机制"而不是"再试一次"解决：
- 本地 python 3.14、服务端 3.10：`marshal.dumps` 出的 code object 在对面报 `bad marshal data`；
- 手搓 pickle 时写 `ctypes.FunctionType`（错模块），应是 `types.FunctionType`。

最后用 itemgetter 链打成 RCE，确认 `uid=0`，直接读 `/answers/flag`；命令输出借
`KeyError` 的 repr 夹在错误响应里带回。27 次工具调用 / 8 分钟。

## 4. 符号 —— 认得键盘就行

### 题面
一个只做一件事的小页面：用一组符号展示本实例的答案，读懂符号还原完整 FLAG。（misc / easy）

### 打法（单步，107 秒 / 6 次工具调用）
- 附件 `readme.txt` 只有一句"你知道这是什么符号吗?"。符号是**注音符号（Bopomofo）**。
- 页面 `div.flag` 里是 32 个注音字母 + 声调符。按**台湾大千式注音键盘**逐字映射到键位：
  `ㄅ→1 ㄆ→q ㄇ→a ㄈ→z ㄉ→2 … ㄓ→5 … ˊ→6 ˇ→3 ˋ→4 ˙→7`。
- 结果 `48d58fd8…03f2` 恰好 32 字符、全是十六进制数字 —— 就是 flag 本体（全站 69 队解出）。

agent 顺手做了证伪：当 hex 解成字节只有 5/16 可打印，GBK/Big5 也不通；32 个字符随机落进
hex 字符集的概率约 10⁻¹³，所以判定"就是键盘映射"而非二次编码。

### 价值
编码/多模态类题不需要模型"看图"：抓出 Unicode 码点 + 一张已知键盘表即可。13.5 万 token。

## 5. 复盘

- **四次成功里三次建立在"本地可复现"上**：先让真源码/真服务在本地跑通，再打远端，
  这样远端只允许一次试错也能成（符号题是唯一纯静态的）。
- **该打的弯路绕不开**：Insecure3PC 前两条路（篡改输出、伪造 triple）都是真漏洞，
  但都被服务端 judge 的独立重算挡住；agent 是在被 `No Cheating` 打回来之后才转向
  输入恢复的。judge 的存在改变了"最优攻击面"。在线模型微调同理：直球 pickle 被
  picklescan 拦了才转去拼白名单 global。
- **预算与题目类型强相关**：纯分析/编码题（Mental Card Game 6 分钟、符号 2 分钟）足够；
  需要自编译 + 打桩的题（Insecure3PC）要 80 分钟以上。
- **三条车道两种模型都用上了**：四个解分别落在 deepseek、qwen4-max、deepseek-flash 上，
  说明多厂商车道是"多一次抽卡"而不只是防 429。
- 后续可做：把"先本地跑通再打远端"写成显式方法卡；对需要编译的题，评估环境里
  预置编译器与依赖（本题 g++ 可用、`Crypto` 缺失，靠 venv 里的 pycryptodome 兜住）。
