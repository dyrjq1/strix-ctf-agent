## 2. 合规风险（按严重度）

**A1（高，契约履行缺口，置信度高）**：官方入口不回答多问题题与 gated questions。
- 现象：`agent.py:298-315` `_question_id` 只取 `questions[0]`；全部 6 处 `answers[qid] = ...`（agent.py:1189,1200,1336,1350）只写这一个 key。CTFY-0001 §2 明确 `gated_questions` 需在答对后重读题目（docs/08:483-488），§3.3 平台会以 rounds 重启镜像（docs/08:947-972）——但重启后 `task.json` 里 `questions[0]` 大概率仍是已答对的 q1，agent 会把新答案继续写到 q1 的 key 上，**新解锁的 q2 永远拿不到分**，直到 5 轮上限耗尽。
- 佐证：多问题支持只存在于评测侧（batch_eval.py:1020-1029 的 `ANSWER[<qid>]=` 协议、1456-1479 按qid提交）；官方入口没有等价物。goal 文件却写着“Answer every question the task declares”（config/ctf_goal.txt:12-13）——指令与管线矛盾。
- 是否违规：不违反规则，但**系统性放弃协议给的得分机会**，正式赛多问题题将一分不得。
- 建议：`agent.py` 收集全部可见 question id，`answers` 按 qid 多键写入；轮次感知可从 README/task.json 的判定信息取（需先在 11-14 平台测试赛实测 rounds 的 task.json 形状）。

**A2（中，置信度中）**：轮次重启后无状态衔接。`/ctfy/work` 跨轮保留（除 result.json，docs/08:962-964），但 `agent.py` 的 instruction 不告知“这是第几轮、上一轮哪些题答错了、笔记在哪”——错误答案可重试的信息（docs/08:953-957）完全丢失。

**A3（中低，置信度高）**：评测与交付镜像三处口径漂移（同一类事故已发生两次：capabilities、sweep_guard，见 ledger 4.41/4.42）：
1. **aisec**：`agent.py:977-984` 在数据目录存在时**无条件注册**（已实测 `src/ctf_strix/aisec/data` 存在，2583 个文件，且 Dockerfile:57 设了 `CTF_AISEC_DATA`）；而 `run_strix_ctf.py:236-244` 默认 `CTF_AISEC=0` 不注册。**评测数字描述的工具面 ≠ 交付镜像实际工具面**，且 aisec schema 常驻每次调用。
2. entrypoint 兜底写 `schema_version: 2`（docker/entrypoint.sh:44,50），主流程写 3（agent.py:593）——advisory 级但属自我矛盾。
3. `run_strix_ctf.py` 的 `--trim-tools` 已是空壳兼容开关（run_strix_ctf.py:44-48）。

**A4（低，置信度高）**：`ctf-similar-search` 技能被 prompt 索引排除（prompt.py:157），但 `skillpack.register()` 仍注册全部 14 个方向——模型直接点名 `load_skill` 仍会载入一篇教它 `pip install tavily` 的文章，白烧轮次（prompt.py:148-156 已论证危害）。

**A5（低，记录在案）**：题目 `description`/`tags` 喂给 agent 属“保守解释、未与主办方书面确认”（docs/12 §4.1）；`batch_eval` 的 tag→首动作映射（29 条，commit P8）来源是已跑题行为，命名测试可过（G 级），但迁移性未经留出集专门验证。

**未发现的违规**：外网（offline stub，tool_trim.py:127-187；无任何 src 模块发起外网调用）；并发（串行轮转，batch_eval.py:3-6；`_attempt_count` 串行 1-3，agent.py:493-504）；实例（v3 下不调 `POST /instances`，agent.py:646-648 注释明确）；token 双花（autosubmit 未挂官方入口，answers 单通道，agent.py:11-17）。

## 摘要（≤20 行）

**总体**：合规面干净——外网全离线桩、单实例串行、无 token 双花、无步数硬编码。真正的问题集中在“正赛形态”与“契约履行”两处。

**最值得先做的 3 件事**：

1. **官方入口多问题支持（建议 1，P0）**：`agent.py` 只把答案写进 `questions[0]` 的 key（agent.py:298-315），多问题题和 gated 题在正式赛一分拿不到，且会空转耗尽 5 轮重启。这是纯契约缺口，评测侧早有等价实现（batch_eval 的 `ANSWER[qid]=` 协议）可平移。
