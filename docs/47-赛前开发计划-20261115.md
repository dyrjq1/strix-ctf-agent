# 47 · 赛前开发计划（2026-11-15）

> 目的：初选赛 11-20 10:00–20:00（UTC+8）与正式赛 11-21 只剩 4 个可用工作日。
> 本文把「还能改什么」收敛成 5 条，按**证据强度 × 预期收益**排序，每条都有物理依据、
> 验收线和回滚路径。凡是证据不足的一律放进「不做」，不带进冻结。

---

## 0 结论先行

在没有顶尖模型的前提下，解出率的最大杠杆**不是让模型想得更聪明**，而是三件可测量的事：

1. **缩短每次 run 的占用时间**——协议 v3 下平台每次 run 只给一道题、单槽串行派发，
   run 时长就是吞吐量的分母（§2 依据 F1/F2/F5）。
2. **把平台已经付费的专家分解接进来**——平台自带 hint 机制且计费是 discount 模式，
   我们一行未接（F6）。这是弱模型上唯一有 2× 实证的杠杆。
3. **把"已解过的题"做成离线检索，而不是塞进提示词**——台账已建但从未进 agent（P2）。

顺序：**P0 早退闸门 → P1 hint 接线 → P2 解法检索 → P3 多 flag 追打 → P4 方法卡首步校准**。

## 2 P0 · 进度证据闸门 + 早退（最高优先）

### 2.1 机制

把 run 的结束条件从「撞预算上限」改成「**没有新信息了**」：

- 复用 `progress_guard.py` / `enum_guard.py` 已有的重复响应计数，新增判据：
  **连续 N 步没有产出新证据**（新端点、新参数、新 id、新假设被证实/否证都没有）。
- 命中后让模型收尾：写 `result.json`、把未解问题数写清楚，干净退出，**不空转到墙钟**。
- 硬墙保持不变（**不降**），只做兜底。

### 2.2 物理依据（为什么这不是"调预算"）

- 失败组 55% 撞上限，成功组 **0%** 撞上限 → 撞上限是失败的**征兆**，不是失败的原因。
- 活着到 40 调用时 P(solve) 只剩 13.8%；到 600s 后 0/15。
- 平台单槽派发（F1/F2）：我们占着槽，平台就没法把下一题派给我们。省下的是**下一次机会**，不是"省点钱"。

**这条改的是结束判据，不是预算数值**：`budget_turns` / `budget_wall_s` 一个不动，红线成立。

### 2.3 为什么必须是"证据判据"而不是"时间判据"

如果平台其实不重派发，早退就是纯亏：会丢掉 11% 的慢解（wall > 300s 的 11 道解出题）。
证据判据把损失压在这部分里最小的一侧——**在打的题继续打，已经打不动的那部分先撤**。
时间判据（例如一律砍到 300s）只有在平台确实重派发时才划算，而这一点**赛前无法证伪**。

### 2.4 验收

| 项 | 线 |
|---|---|
| 单测 | 基线 1846 passed / 7 skipped 不减；新增「该响的时候响」+「不该响的时候不响」两侧用例 |
| 行为 | 离线重放历史 run（`agents.db` item 流，零 token）：闸门在**已解出**的 run 上触发率 < 10% |
| 消融 | 撤掉闸门跑同一批题；解出数不降、总时长下降才算有效 |

### 2.5 回滚

一个 config 开关置 OFF 即恢复原行为；台账记一行。不改默认预算值，所以回滚无连带影响。

## 3 P1 · hint 接线（弱模型上唯一有 2× 实证的杠杆）

### 3.1 机制

平台把 hint 作为 MCP 工具暴露（`list_hints` / `view_hint`），且本题计费是 **discount**：
开提示只封顶本题收益（`cost_percent`），**不扣总分**。在动态衰减已经把所有晚解题压到
10% 下限的赛制里，这个代价基本可以忽略。

改动：给 agent 一个 hint 工具，配闸门——**卡住 ≥ N 步才允许调用**，避免第一轮就要答案。

### 3.2 物理依据

- 外部实证：Cybench 上 405B 在给定分解/提示时 7.5% → 15%（约 2×），这是"没有顶尖模型"场景下
  唯一被反复复现的增益机制。
- 我方失败面：40 道零解出里 14 道是能力缺口（`docs/24` 套路缺口清单），hint 正好补这个缺口，
  且**不引入过拟合**（提示是题目作者写的，不是我们对着失败日志编的）。

### 3.3 风险与前提

- 入围赛 5 题 `hints_released = 0`、`list_hints` 返回 404 → **这个比赛的题可能压根没有 hint**。
- 所以：先做**可用性探测**（一次 `list_hints`，空则整条链路永久静默，不许重试烧预算），
  再决定是否把它当作主要杠杆。11-20 开赛十分钟内就能知道答案。

### 3.4 验收

探测到 `hints_released > 0` 的题才算接线成功；A/B 在**未解题**上比解出率（不看分数，分数受衰减污染）。

## 4 P2 · 离线解法检索（自家台账进 agent）

### 4.1 现状

`docs/44-解出题解法台账` 已建：99 条解法记录 / 74 道题，含方法、工具链、结论。
但它是**文档，不是工具**——agent 看不到。

### 4.2 为什么不能直接当方法卡塞进提示词

- 99/99 条解出记录里**方法卡一张都没注入过**（`experiments/card_ab_corpus.json`），说明
  "解法"不是靠提示词给的。
- 按标签路由会把无关题误导进去（`docs/44` §2 已实测）。

### 4.3 做法

做成**按需检索**：agent 显式调用时，按「题型 / 工具 / 首个线索形态」返回 ≤ 400 字的检索结果，
不进 system prompt、不常驻上下文。外部依据：CTFAgent 消融显示去掉自家 writeup 检索后 73%→61%。

### 4.4 验收

只在**未解过的题**上量；已解题上量不出东西。检索空命中率必须 < 30%，否则是噪声。

## 5 P3 · 多 flag / gated 题追打闭环

协议 §2 点名的掉分点：`gated_questions > 0` 时，答对一题后必须重读 challenge 端点，
后续问题才解锁；「只答第一题就停」会拿到一小部分分数并**看起来像放弃**。

我方现状：`autosubmit.py:457` 的 G1 已经会重读并把未解锁题回写给模型，入围赛 4 checkpoint 全取。
缺口是**回写 ≠ 推动**：没有把"还有未解问题"变成收尾的硬性条件。

改动：`gated_questions > 0` 且仍有未解问题时，收尾动作必须显式回答"为什么不继续"
（写进 result.json 的 summary），而不是静默结束。

## 9 不做什么（本轮到冻结为止）

- **不做跨题调度器**：协议 v3 下不存在这个自由度（F1）。任何"选下一道更划算的题"的设计都是空转。
- **不降预算数值**：`budget_turns` / `budget_wall_s` 不动；P0 改的是结束判据。
- **不做 planner+executor 多智能体**：外部实测 Sonnet 规划 + Haiku 执行 13.0% 低于单 Sonnet 19.0%；
  且隔壁队已自证协调税（重派 26 万 token）。
- **不把 shell 换成结构化工具**：外部实测「用专用 read_file 替代 cat」的 agent 解出率 17.7% vs 70.6%。
  我们已有的结构化原语是**补充**，不是替代。
- **不在 ≤6 样本的聚类上调参**（`docs/45` 已列）。
- **不动 `experiments/pools.json`**（SHA256 `55da418b…678`）。
- **不改 `vendor/`**。

## 11 一句话验收

到 11-19 冻结时，本计划只认两个数字：**全量测试 ≥ 1846 passed**，
以及**离线重放中早退闸门在已解出 run 上的误触发率 < 10%**。
其余（分数、名次、单批解出率）一律不作为通过依据。
