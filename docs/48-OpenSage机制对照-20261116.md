## 1. 它到底做了什么（五件套 + 一份提示词）

| # | 机制 | 代码 | 要点 |
|---|---|---|---|
| 1 | **动态造 agent** | `src/opensage/toolbox/general/orchestration_tools.py:377` `create_subagent(agent_name, instruction, model_name, tools_list, enabled_skills)` | 模型自己写子 agent 的 instruction / 选模型 / 选工具，注册后持久化（`save_agent_definition`），可跨重启重建。这就是「AI 生成的拓扑」 |
| 2 | **子 agent 默认空上下文** | 同上 `:89` `use_parent_history: bool = False`；`orchestration/manager.py:433-510` `_build_child_state` | 只有 `use_parent_history=True` 才继承父的全部 events/state；默认只给一条 request。**子 agent 比自己做便宜**，不是更贵 |
| 3 | **异步 + 自动唤醒** | `orchestration_tools.py:97-101` `mode="async"`；`manager.py:745-775`（写 inbox + `_wake_queue.put`） | 派完立即返回，结果完成后写回调用者 inbox 并**唤醒睡眠中的调用者**；root 不必阻塞等待 |
| 4 | **广播** | `orchestration_tools.py:193-213` `send_message(to_session_id="*")`；`manager.py:722-743` | 一条消息打给**所有存活实例**（除自己），fire-and-forget；收件人在下一个工具边界或下次唤醒时看到 |
| 5 | **实例生命周期** | `orchestration/types.py:22-33`（RUNNING/SLEEPING/TERMINATING/TERMINATED）、`manager.py:643` dispatcher | 实例可睡眠、可被消息唤醒、可永久终止；`list_subagents` 让模型自己看拓扑 |
| 6 | **消息注入格式** | `manager.py:1328-1400` `_format_messages_block` / `_build_user_content` | 注入时包 `[Incoming peer messages]` + 一段纪律（「这不是新的用户请求，无关就继续你自己的任务」）。**广播不等于打断** |
| 7 | **多模型编排** | `orchestration_tools.py:327` `get_available_models`、`call_subagent(model_name=...)` | 逐次调用可换模型；SageCTF 实测 root=GPT-5.5、深度活=Opus-4.6、广度活=DeepSeek-V4-Pro |
| 8 | **强制委派提示词** | `agent_library/local_support/tbench-agent/sage.py:56-143` | 原文：「**CRITICAL: You MUST use subagents for every non-trivial task. This is not optional.**」，并列出「没用子 agent = 失败」的判定条件；开工先 `get_available_models` + `list_subagents` |

规模参照（博文）：7 题解出、**23,919 次模型调用 / 2.4B token**，平均每题 ~3,400 次调用、~5 小时。

## 2. 我方现状（对着看）

| 维度 | SageCTF | 我方（`src/ctf_strix/parallel.py` + `prompt._RACE`） |
|---|---|---|
| 默认值 | 委派是默认且强制 | **默认关**；开也只说「两个互斥且可用现有证据证伪的方向才派」 |
| 上限 | 无硬上限，可递归（子生子） | `MAX_SUBAGENTS = 2`，子不得生子 |
| 子 agent 上下文 | 默认**空**（`use_parent_history=False`） | vendor 默认 `inherit_context=True` → **继承父全量上下文** |
| 派出成本 | 一次 `call_subagent` | `create_agent` docstring 要求先 `view_agent_graph`、建议带 skill → 两次前置调用 |
| 通信 | 全实例广播 + 定向消息 | **无广播**；vendor `send_message_to_agent` 是一对一 |
| 等待 | async + 完成自动唤醒 | 子 agent 同 run 内跑，root 只能靠轮次推进 |
| 胜利处理 | root 自己整合 | **先拿到 flag 即停兄弟 + 唤醒 root**（这条我们比它强，保留） |
| 模型 | 每次调用可换 | 单端点单模型 |
| 记忆 | 短期 `pinned.md`（compaction 安全）+ `/mem/long_term/` 共享 wiki | 单 run 的 `traffic` 台账 + `evidence` 链，无跨 agent 共享 |
| 单题调用量 | ~3,400 | **35**（§4.246 四臂实测 30-39） |

## 3. 差距排序（按「对解出率的杠杆 / 改动风险」）

| 级别 | 缺口 | 为什么杠杆大 | 改动量 |
|---|---|---|---|
| **G1** | 提示词写的是「默认自己解」 | 四臂实测 spawn=0，reasoning 254 条里 0 条把「派子 agent」放进动作集。**机制没被拒绝，是没被想起** | 改 `_RACE` 一段 |
| **G2** | 成本方向反了 | 我们的子 agent 继承满上下文 + 两次前置调用 ⇒ 比自己干更贵；它做成了「子 agent 更便宜」，模型自然愿意派 | `inherit_context` 默认 + 去掉 `view_agent_graph` 前置（接线类） |
| **G3** | 无广播、无异步 | 「多点探索」缺了「探索成果互相看见」，两个子 agent 各干各的；root 也是同步等 | 中，需要一条 sender 注入路径 |
| **G4** | 预算尺度差 100× | 35 次调用的 run 里，2 个子 agent 的结构性开销（规划 + 整合 ≥ 8 次）就吃掉 1/4 预算 | 预算必须依附 G1/G2 一起动，不许单独动 |
| **G5** | 单模型 | 广度搜索可以用便宜模型铺量，深度用强模型；这是「同等预算下解出率」最直接的一刀 | 依赖网关侧模型可用性，未核 |

## 4. 实验设计（一次只改一处，先定后看）

- **E1（G1，只改提示词默认值，不动预算）**：把 `_RACE` 从「例外才派」改成 SageCTF 式强制派（但保留 MAX=2、保留「先答者停兄弟」）。
  预注册题池：CTFARENA 本队从未解出且未封存的题，按历史 run 数降序取 3 道。
  判据：① spawn 率 > 0（这是机制可达性，必须先过）；② 同题调用数不涨 30% 以上；③ 解出率不劣于 OFF 臂。三条全过才进 E2。
- **E2（G2，接线类，可与 E1 合并）**：`inherit_context` 默认改 `False`；子 agent 不再强制 `view_agent_graph`。
- **E3（G3，广播）**：把子 agent 的发现做成一条 `send_all`（兄弟可见），注入格式照抄 `_format_messages_block` 的纪律段。
- **E4（G4，预算）**：**只在 E1+E2 出现「有 spawn 且方向不重复」之后**才提预算，依据写物理量：单次模型往返 5-8s、2 子 + root 的结构开销 ≥8 次调用。
- **不做**：不照搬递归子 agent（内存受限，历史出过 exit 137）；不照搬 `create_subagent` 的任意工具面（会击穿我们的工具裁剪与 F2 计数）。

## 5. 回滚与验收

- 每步单独 commit，回滚 = `git revert <sha>`。
- 验收口径按 CLAUDE.md §11 八条；E1 的「spawn 率 > 0」必须来自 `result.json` 的 `parallel.stats().spawned`，不看日志印象。
