# 29 strix 1.7.0 与本仿制版的能力差距盘点（2026-11-03）

> 角色：worker G（只读盘点）。未改生产代码、未跑 pytest、未跑题、未写任何 token/凭据。
> 对照物：`vendor/src/strix`（strix 1.7.0 原样拷贝）与 `src/ctf_strix` 当前实现。

## 0. 结论先行

最重要的结论不是「上游有 65 条技能、我们只有 13 条」，而是三点：

1. **当前提示把 `read_file` 当成存在的工具，但工具面里没有它。** 这是契约 bug，不是能力差距；修它零 token 成本，优先级高于补任何知识库。证据：`src/ctf_strix/prompt.py:301-305`、`src/ctf_strix/skillpack.py:136-140`、`:235-240`、`src/ctf_strix/catalogue.py:75-80` 都要求 `read_file`；SDK Filesystem capability 只挂 `view_image` / `apply_patch`（`.venv/Lib/site-packages/agents/sandbox/capabilities/filesystem.py:14-41`），Shell 只挂 `exec_command` / 可选 `write_stdin`（`.venv/Lib/site-packages/agents/sandbox/capabilities/shell.py:28-33`），vendor factory 只挂这两个 capability（`vendor/src/strix/agents/factory.py:723-742`）。`vendor/src/strix` 全目录对 `read_file` 零命中。
2. **差距最大的是方向纠偏，不是知识量。** 失败题 p50 267–551 秒、成功题 60–70 秒（`docs/23-覆盖矩阵与对标.md:128`、`docs/25-防过拟合守则.md:42`），说明瓶颈是选错方向后越陷越深。短而硬的反证/换机制判据，优先级高于 65 篇长文。
3. **上游 65 条只有一部分是方法论，另一部分是环境假设。** 65 条共 647,726 字符（~161,932 token，按 4 字符/token 粗估）；tooling/cloud/AD/browser 类大量句子直接命令 `nuclei`/`ffuf`/`sqlmap`/`kubectl`/`agent-browser`，镜像没有这些二进制（`docker/Dockerfile:21-34`）。

## 1. 方法与口径

- **只读**：`vendor/` 未改一行；未跑题、未跑 pytest、未发网络请求。
- **行号**：按当前工作区文件实际行号；技能按 `vendor/src/strix/skills/<category>/<name>.md` 计。
- **token**：无真实分词器时按 `字符数 / 4` 粗估并标 `~`，仅用于量级排序。
- **工具面字符**：`description + params_json_schema` 的 JSON 字符串长度，实测自 `factory._BASE_TOOLS`。
- **可执行判据**：只问“容器里真的能跑吗”。纯知识/纯本地（curl、Python、文件解析）算可执行；依赖不存在二进制、云凭据、浏览器、MCP、外网的算不可执行。

**当前仿制版有同题跨轮，但没有跨题**：

- `agent.py:350-401` 的 `_round_note()` 读工作目录 `README.md`，跨轮注入上一轮 verdict / newly unlocked；调用点在 `agent.py:1536-1540`。这是**同一道题的不同轮次**，不是跨题。
- `attempt_digest.py:1-10`、`:188-194` 是**同题失败重试**的确定性摘要；P16 A/B 未通过，`CTF_ATTEMPTS` 默认 1（`docs/16:243-265`、`agent.py:1593`）。

**正式赛 7 天连续作战，跨题记忆值不值得做？**

**初步结论：值得做，但不该先做；而且只能做“按 tag 的 3 行机制经验”，不能做全局记忆库。** 理由：

- **正向证据弱**：`docs/16:72-92` 的 STRIATUM 文档实验最大只有 +8.9pp，且 `p=0.77` / GEE `p=0.29` 不显著；唯一被文档翻盘的是 heap overflow（具体技术笔记，不是泛泛方法论）。
- **同题重试都没过**：P16 没有多解出任何一题，token 平均 1.42×（`docs/16:243-254`）。跨题记忆比同题重试更难归因。
- **污染风险真实**：把上一题的错误结论带入下一题，会形成“锚定 + 自我强化”；CTF 题目之间差异大，tag 粒度太粗时尤其危险。
- **已有设计雏形**：`docs/16:309-312` 的 P19 明确“只记录哪类题、第几次调用、哪个原语首次拿到新信息，不记录 flag；下一题按 tag 注入最多 3 条；若 P16 A/B 没有增益就不做”。这是正确的边界。

**如果要试，最小实验**：先在同 tag 的 reserve 题上做“无记忆 vs 3 行 playbook”，只记录“机制 → 首次新信息”，不记 flag/路径；验收用留出集 ≥5pp（`CLAUDE.md:219`），否则停。

## 4. 前 5 名的验证实验设计

> 共同约束：题源只用未参与本轮开发的 reserve 或封存题。`experiments/pools.json` 当前实测 **diagnostic=19、reserve=12、burned=79**，另有 `sealed_excluded` 20 个 ID（官方封存集，不参与切分）。我们自己的留出集是 `docs/25` §3.1 的 20 道（seed=20261101），**开发期禁跑、定稿前只跑一次**。禁止用 burned 的 79 道，也禁止用已 “Burned after run” 的 diagnostic 19 道；禁止把失败日志里的具体路径写进 prompt。

> **现实约束（重要）**：reserve 12 道全部是 `CTFARENA` web 题（`pools.json` 实测：2 hardest + 7 hard + 3 medium），练习赛又是“全 web、零附件”（`CLAUDE.md:48`）。所以下面各节写的 file/rev 题源在 reserve 里**不存在**，只能记为“无同分布题可验”，或用 burned 的历史基线做回归对照（不能当提升证据）。每组同模型、同实例、同轮次预算；一次只改一个变量。5 组共用 reserve 12 道，不要一组一批。

### 4.1 `read_file` 契约修复（排名 1）

- **题源**：从 reserve 抽 6 道“会触发技能索引”的 web 题（不要求附件）；file/rev 部分标为“无同分布题可验”，只在 burned 历史基线上做回归。不用 burned 当提升证据。
- **臂**：A=旧提示（`read_file`）；B=新提示（`exec_command cat <path>` / `view_image`）＋相关测试断言改为真实工具名。只改字符串与测试，不改注册逻辑。
- **指标**：日志中 `read_file` not-found 次数、技能子文件成功读取率（输出出现子文件内容）、首次获得新信息的轮次、解出率、总 token。
- **消融**：撤掉新字符串回旧版，同题同预算重跑；若 not-found 错误率回升或首解轮次变差，判为有效。
- **验收**：B 臂 not-found 为 0；提示长度不增加。若模型本来就改用 `cat`、指标无变化，仍应合并（契约正确性），但不计入提分。

### 4.2 反证/闭合 + 换机制提示块（排名 2）

- **题源**：reserve 中 6 道 subtle logic web 题（prototype pollution、origin trust、business logic、错误处理、postMessage/DOM XSS 各 1-2 道）；reserve 无 easy 题，“easy 控制题不倒退”只能用 burned 历史题做回归对照，不算提升证据。
- **臂**：A=当前提示；B=当前提示＋600-1,500 字符的“三态闭合＋负控制＋同响应族换机制”块。
- **指标**：不同机制尝试数（按 `think`/工具参数分类）、重复探测数、首次新信息轮次、解出、token；easy 控制题不得变差。
- **消融**：撤掉该段同题同预算重跑；若只有某一题变好，按命名测试标 S 级并写清触发条件，不得当成通用提升。
- **验收**：reserve 解出提升 ≥5pp，或失败题 p50 明显下降；不能只看开发题。
### 4.3 选定技能恢复（排名 3）

- **题源**：reserve 12 道里挑 8-10 道 web 题，覆盖至少 3 个目标类别（逻辑/权限、注入、解析器/文件）；先剔除与 `ctf-web` 已覆盖内容重叠的题。reserve 不够就减到 6 道，不要拿 burned 充数。
- **臂**：A=当前 13 索引；B=当前 13 + 选定 10-15 条改写版 vendor 索引；C=负控制（加 10-15 条**无关**技能索引），用于区分“知识有效”与“单纯多 token”。
- **指标**：解出、首次新信息调用、技能加载次数、单请求常驻 token、技能子文件读取率。
- **消融**：撤掉新增索引，同题同预算重跑；若 B 只在 C 也提升的题上提升，判为 token/注意力效应，不是知识效应。
- **验收**：reserve ≥5pp（`CLAUDE.md:219`）；叠加索引常驻 ≤500 token。

### 4.4 紧凑 threat_model + coverage（排名 4）

- **题源**：6 道多步 web 题（reserve 内事先固定）；长 pwn/rev 在 reserve 里无同分布样本，只能在 burned 历史基线上做回归，不作为净收益证据。
- **臂**：A=无状态；B=一个 JSON/Markdown 状态文件（或最多 2 个工具：threat_model + coverage）。
- **指标**：重复探测/重复路径率、不同假设数、首次新信息轮次、解出、token；`needs_follow_up` 项是否被后续闭合。
- **消融**：只撤状态工具、保留提示不变；若撤掉后重复率上升或解出下降，判为有效。
- **验收**：失败题中确实出现“重复已排除路径”才可能净赚；若只是增加记账调用、解出不变，回滚。

### 4.5 子 agent 条件开启（排名 5）

- **题源**：6 道 broad/multi-direction 的 reserve web 题（大 web/source、多假设逻辑题）；不要 easy。pwn/rev/misc 无同分布题，不纳入本轮验收。
- **臂**：`CTF_ALLOW_SUBAGENTS=0` vs `1`；总轮次预算相同；同模型、同实例。
- **指标**：`scripts/measure_swarm.py` 的 `child_expensive`/`child_effective`、协调调用占比、任务提示/回灌字符、首解轮次、墙钟、解出。
- **消融**：`ALLOW_SUBAGENTS=1` 但子 agent 只做只读侦察 vs 全做；区分“并行收益”与“协调成本”。
- **验收**：只有 child 有效工作且首解更快/更稳才保留；25% 单样本不能当依据（`docs/11:1827-1828`）；连续两题没有净赚即继续默认关。

## 5. 反方论证：看起来大、但不该补的差距

> 这一节故意站在“不要恢复”的一边。每条都过同一道检验：**容器里真的能跑吗、跑了真的更省吗**。凡是答案是否定或不确定的，都不进决策表。

### 5.1 “65 条 vs 13 条”主要是环境差，不是知识差

- **体量本身不构成理由**。65 条 647,726 字符（~161,932 token）里，tooling 13 条 65,230、cloud 4 条 51,042、technologies 7 条 100,199，三类合计 216,471 字符（33.4%），主体是外部工具/云控制台/AD 环境的操作手册。镜像只有 `curl/wget/git/jq/file/xxd/binutils/gdb/strace/ltrace/netcat/dig` 等基础包（`docker/Dockerfile:28-34`），且 **agent 进程无外网**（`CLAUDE.md:50`）。这三类不是“知识没学到”，是“题面里的环境不存在”。
- **上游自己也承认文档的边际收益接近零**。STRIATUM 180 次实验里，全量文档 86.7% vs 最小文档 77.8%，差 4/45 = +8.9pp，作者自己的 Kruskal–Wallis `p=0.77`、GEE `p=0.29`（`docs/16:78-84`）。唯一被文档翻盘的是一道 heap overflow，靠的是 353 行**具体技术笔记 + 可执行步骤**，不是泛泛方法论（`docs/16:85-88`）。
- **本项目已经据此做过一次裁决**：“停止扩充技能文档……把预算转向可执行原语和具体题型的 worked example”（`docs/16:90-92`）。现在再按“上游有 65 条”恢复，等于推翻这条已有结论，而新增证据并没有出现。
- **重叠比缺口大**。当前 `ctf-web` 已有 26 个 md / 592,148 字符（~148k token），SQLi/SSTI/SSRF/反序列化/race/XSS/JWT/OAuth/原型链都有独立章节；真正零命中的只有 `business logic` 与 `semantic confusion`（`src/ctf_strix/skills_strix/ctf-web/` 全目录实测）。恢复 25 条“可整类”技能，大部分是在已有 148k token 上再叠一套同主题文档，收益无法归因，冲突风险却是实打实的。

### 5.2 103k 系统提示不是“更聪明的提示”，是另一个产品的提示

- **它假设的角色与我们相反**。vendor 开头就写 “YOU ARE THE ROOT AGENT. Your job is ORCHESTRATION, not hands-on testing... you do NOT run scanners, crawlers, fuzzers, or send exploit payloads yourself”（`vendor/src/strix/agents/prompts/system_prompt.jinja:5-9`）。我们是单实例、单模型、必须自己 `curl` 的 CTF agent。恢复这段不是补能力，是让模型拒绝干活。
- **它假设的预算是我们的 50 倍**。“PERSISTENCE IS MANDATORY... expect to need 2000+ steps minimum... If one approach fails, try 10 more approaches”（`system_prompt.jinja:411-417`）。我们的默认预算是 25-40 轮（`src/ctf_strix/tool_trim.py:83-84`），正式赛读 `task.json.max_turns`（`CLAUDE.md:77`）。这句话在 28 轮里等于“把预算烧在同一个方向上”。
- **它列的工具一半不存在**。`system_prompt.jinja:420-495` 声称有 nmap/sqlmap/ffuf/nuclei/subfinder/Caido/browser/apt/pip；实际镜像没有这些二进制（`docker/Dockerfile:28-34`），Caido 是硬阻塞（`docs/01:99-105`），MCP 无 server（`docs/11:1642`）。提示里写不存在的工具，模型会去调用，然后白烧轮次——这正是 `docs/11:1651-1656` 记录的失败模式。
- **常驻成本是硬账**。22,817 token/次 × 40 轮 ≈ 91 万 token 的前缀，还没算工具 schema 和轨迹。当前提示 `build()` 实测 3,485-3,530 字符（core 2,921-3,486 加技能索引，`docs/11:2019` + 2026-11-03 实测）。把 22.8k token 常驻换 +8.9pp（且不显著）的文档收益，在任何预算模型下都不成立。

### 5.3 MCP / Caido / 浏览器 / 扫描器：硬缺失，不是能力差距

- **MCP 5 件套**：容器无 MCP server、平台不下发 `mcp_connection_requests`、镜像内无 `~/.strix/mcp-servers.json`；历史零调用，占 3,355 字符（24.5%）（`docs/11:1642`）。恢复只能得到 5 个必然报错的 schema。
- **Caido 6 件套**：`caido`/`caido-cli` 本机不存在，连续 8 个 release 的 assets 为 0（`docs/01:103`）；6 个工具是 Caido GraphQL 薄封装（`docs/01:101`）。实测 9,690 字符（~2,422 token）/次，历史零有效调用（`src/ctf_strix/tool_trim.py:60-70`）。自建代理要 400-600 行且当前 `tools/proxy` 无抽象层（`docs/01:111`）——那是独立项目，不是“补差距”。
- **浏览器**：`agent_browser` 20,852 字符，正文 155 次 `agent-browser` 调用（`vendor/src/strix/skills/tooling/agent_browser.md:3,7,10`），镜像无此二进制。DOM XSS/admin bot 题在练习赛 **零附件、全 web 但无浏览器**（`CLAUDE.md:48`）；真遇到只能在服务端找替代路径，或明确记为 `open_proof_gap`。
- **扫描器**：ffuf/nuclei/sqlmap/nmap/subfinder 等在镜像里都没有（`docker/Dockerfile:28-34`）。`sqlmap` 尤其危险：它会把“跑一遍工具”当成进展，而镜像里根本没有这个命令。
- **反方结论**：这四类应当从“差距清单”里划掉，改记为“环境约束”。它们不是我们做得差，是题目环境不给。
### 5.4 子 agent：默认关是对的，别被“多 agent 更强”带跑

- **单实例、单模型、共享预算**。root 与子 agent 共用同一块 28 轮预算（`docs/11:1774-1776`）；子 agent 的每次请求还要继承父历史前缀（`docs/11:1768-1770` 明确说这项日志不记录）。
- **唯一可测样本是负收益**。SAMPLE-006：12 次调用里 3 次纯协调（25.0%），父侧还付 2,681 字符任务提示 + 4,036 字符回灌；结论 `child_expensive`（`docs/11:1782-1787`）。子 agent 那 3 次 `exec_command` 确实是高质量工作（`docs/11:1791`），但**质量高不等于总账划算**：25% 协调占比要求它比单 agent 快 33% 才打平（`docs/11:1793`）。
- **25% 不能外推，但也不能反向外推成“大题一定赚”**。原文只说“这是一道题的单个样本，不能据此给所有题型下结论”（`docs/11:1827-1828`），并没有说多方向题一定净赚。现有证据是“有一个负样本 + 无数值”，正确动作是条件实验，不是默认打开。
- **反方结论**：子 agent 留在“条件实验”档，不进默认路径；任何“多 agent 更像人”的直觉都不能替代 `scripts/measure_swarm.py` 的 `child_expensive` 判据。

### 5.5 完整记账/报告工具集：会重演 27.6%

- **A 组实测**：123 次调用里 34 次是记账类（coverage/notes/threat_model/report/graph），占 27.6%，对拿 flag 零贡献（`docs/02:109-123`）。B 组摘掉后降到 0 次（`docs/02:120`）。
- **这不是模型不听话，是工具面给了它“交作业”的出口**。`create_vulnerability_report` 在 VM 上还因缺 `cvss` 必然报错（`src/ctf_strix/tool_trim.py:202-205`），恢复它等于恢复一个必败调用。
- **todo 的历史更直接**：零调用占 4,212 字符（30.8%），比任何一组都贵（`docs/11:1643`）。
- **反方结论**：只可能恢复 1-2 个“状态原语”（threat_model/coverage），且必须证明它减少重复探测；17+6 全套默认恢复没有讨论价值。

### 5.6 跨题记忆：正向证据比宣传弱得多

- **vendor 自己也没有跨题记忆**。`threat_model` 明确 “It does not outlive the scan... a new scan against the same host or checkout starts with no model”（`vendor/src/strix/tools/threat_model/tools.py:1-15`）；其余 notes/coverage/todos 都挂在同一 run 的 `state_dir`（`runner.py:276-284`）。
- **我们已有的同题重试都没过**：P16 三道题 A/B 都没多解出，token 平均 1.42×（`docs/16:243-254`）。同题摘要都带不动方向，跨题 3 行 playbook 更难归因。
- **文档实验的正向信号不显著**：+8.9pp 但 `p=0.77` / GEE `p=0.29`（`docs/16:78-84`）；唯一翻盘的是具体 heap 笔记（`docs/16:85-88`），不是“上一题经验”。
- **污染是真实风险**：CTF 题之间差异大，按 tag 注入会把上一题的错误结论带成锚点。`docs/16:309-312` 的 P19 已经写明边界：不记 flag、最多 3 条、P16 无增益就不做。
- **反方结论**：7 天连续作战确实有“重复踩坑”的痛点，但当前证据不足以支持先做跨题记忆；先做同题方向纠偏（§4.2/§4.4），有净收益再谈跨题。

### 5.7 我们自己的 `ctf-web` 也不是干净基线

恢复 vendor 技能之前，先承认当前包同样有“环境假设”：

- `ctf-web.md:20` 要求 `pip install sqlmap flask-unsign requests httpx`，`:25` 要求 `apt install hashcat`，`:35` 要求 `go install ffuf`——这些在无外网、无 Go 的镜像里都装不上（`CLAUDE.md:50`、`docker/Dockerfile:28-34`）。
- `ctf-web.md:49` 把 Playwright MCP / Burp MCP 写成可选前置；但容器既无 MCP server 也无 Burp（`docs/11:1642`、`docs/01:103`）。
- `ctf-web.md:123` 的 `git clone PayloadsAllTheThings` 需要外网；`ctf-web.md:131-135` 直接给 `ffuf`/`sqlmap` 命令。
- 实测 26 个 md 里，`ffuf` 15 处/4 文件、`sqlmap` 5 处/3 文件、`git clone` 12 处/4 文件、`Playwright` 40 处/3 文件、`Burp` 75 处/8 文件。
- **这说明**：技能恢复的第一道工序不是“从 vendor 搬”，而是**先给现有 26 个文件做同样的离线可执行性清洗**。否则新增的 15 条只会把同类噪声再放大一遍。
